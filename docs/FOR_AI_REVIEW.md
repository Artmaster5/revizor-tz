# Ревизор ТЗ: карта проекта

## Summary (English)

«Ревизор ТЗ» (Requirements Reviewer) is a Python command-line agent (also a local browser window, `python main.py --ui`) that checks a software requirements document before development starts and writes a report in Russian. Every finding carries a verbatim quote and a line number, and the program (not the model) verifies each quote against the document. The verdict, readiness indexes and all numbers are computed by code.

- Nine-stage pipeline: 82 main rules + 8 advisory rules run without any model; model stages (per-requirement lenses, set checks, critic, skeptic) are optional.
- Runs with no key, for free: `python main.py --input docs/requirements.md --output reports/my_report.md --provider offline`.
- Providers: Anthropic, Google Gemini, OpenAI-compatible servers, Ollama / any local OpenAI-compatible server, offline (`revizor/llm/`).
- Clarification loop: questions to the author with options and an assumption, answers, re-check, «было → стало» diff, rewritten requirements (`*.fixed.md`), letter by addressee.
- 1263 tests in 56 test files (`tests/`), no network and no keys. Measured results and method: `eval/ACCURACY.md`; two runs from 27.11.2026 (free Gemini, local Gemma 4) are stored in `docs/runs/`.

## 0. Кратко

«Ревизор ТЗ» проверяет документ с требованиями до начала разработки и пишет отчёт на русском языке: дефекты с дословной цитатой и номером строки, вопросы автору, письмо автору, черновики приёмочных тестов, переписанные формулировки требований, вердикт «можно ли начинать». Работает из командной строки (`main.py`) и в окне браузера на этом же компьютере (`python main.py --ui`). Версия в репозитории — `1.5.1` (`revizor/__init__.py`).

Принцип: порядок шагов, цитаты, номера, индексы и вердикт ведёт программа; модель даёт смысловые замечания, вопросы и формулировки, а каждый её ответ проверяется (`docs/ARCHITECTURE.md`).

## 1. Быстрый запуск без ключа

Нужен Python 3.10 или новее (`requirements.txt`).

```bash
python3 -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python main.py --input docs/requirements.md --output reports/my_report.md --provider offline
```

Режим `offline` работает без ключа, бесплатно и без сети; документ никуда не уходит. На документе организаторов он даёт отчёт с 27 замечаниями (3 блокера) и сохранён в `reports/report_offline.md` (`README.md`, `reports/README.md`). Время прогона без модели — 0,3 с (`README.md`, таблица режимов). Рядом с отчётом пишутся файлы анкеты, письма, тестов, Jira CSV, JSON и HTML-страница (раздел 3).

Окно в браузере (адрес `127.0.0.1`, порт по умолчанию 8765 — `revizor/cli.py`, параметр `--port`):

```bash
python main.py --ui
```

С моделью: положить один ключ в `.env` (образец — `.env.example`) и запустить ту же команду без `--provider offline`; провайдер выбирается автоматически по найденному ключу в порядке Anthropic, Gemini, OpenAI, Ollama (`revizor/llm/__init__.py`, `revizor/cli.py`: `AUTO_ORDER`) или параметром `--provider` / переменной `LLM_PROVIDER`. Цену можно узнать заранее: `--estimate`.

## 2. Конвейер: девять этапов

Источник: `revizor/pipeline.py`, `docs/ARCHITECTURE.md`, `README.md`. Терминал и окно показывают те же девять этапов с секундами каждого.

| № | Этап | Что делает | Модель | Файлы |
| :-: | :--- | :--- | :--- | :--- |
| 1 | Чтение и маскирование | читает `.md`, `.txt`, `.pdf`, `.docx`, `.html`; разбирает текст на блоки с номерами строк; заменяет звёздочками номера карт, ИИН/БИН, почту, телефоны | нет | `loader.py`, `structure.py`, `privacy.py` |
| 2 | Нарезка на требования | делит блоки на требования, номера `REQ-…` выдаёт программа | модель или эвристика программы (без модели, а также в режиме экономии Gemini — эвристика) | `slicer.py`, `pipeline.py` |
| 3 | Правила без модели | 82 основных правила и 8 «наблюдений» (число берётся из реестра `RULES`) | нет | `rules/` |
| 4 | Проверка каждого требования | три линзы: ясность; полнота и проверяемость; корректность | да | `prompts.py`, `merge.py` |
| 5 | Проверка набора целиком | противоречия, полнота, стандарты и безопасность, критик «чего не хватает» по 35 контрольным вопросам | да | `prompts.py`, `gapcheck.py` |
| 6 | Сверка цитат и слияние повторов | ищет цитату в тексте документа; замечание без найденной цитаты выбрасывается и считается; повторы сливаются | нет | `quotes.py`, `merge.py` |
| 7 | Перепроверка («скептик») | второй независимый взгляд: оставить, объединить повтор или отнести к наблюдениям; находку правила снять не может; решение применяет программа | да | `gate.py` |
| 8 | Вопросы автору, допущения, письмо, тесты, формулировки | вопросы составляет модель (без модели — шаблоны правил); допущения, адресаты, отпечатки, проверка исправления, письмо — код | модель + шаблоны | `clarify.py`, `testgen.py`, `rewrite_gate.py`, `impact.py` |
| 9 | Индексы, вердикт, готовности, отчёт | считает индексы ясности и готовности, вердикт, две готовности; пишет отчёт и файлы рядом | нет | `score.py`, `verdict.py`, `readiness.py`, `report_md.py`, `exports.py`, `sidefiles.py` |

Без модели (`--provider offline` или нет ключа) этапы 4, 5 и 7 пропускаются; вердикт помечается предварительным (`docs/ARCHITECTURE.md`, `revizor/verdict.py`: `OFFLINE_TAIL`).

## 4. Точность

### 4.1. Метод

Источники: `README.md` (таблица в разделе «Точность»), `SUBMISSION.md`, `eval/ACCURACY.md`.

- Три числа рядом: «строго» и «по месту» считает программа `eval/score.py`; третье число ставит независимый судья — ИИ-модель в отдельной сессии, которая не видела ни оценок программы, ни переписки. Судья один и тот же для всех моделей; задание судье — `eval/judge/BRIEF.md`.
- «Строго»: цитата замечания стоит на том же месте документа, что и дефект ключа, и в тексте замечания есть ключевые слова дефекта. «По месту»: совпало только место. Правила сопоставления записаны в шапке `eval/score.py`.
- Ключи дефектов заморожены до прогона. Ключ документа организаторов — `eval/docs/requirements.md.key.json` (52 дефекта, из них 10 назвали организаторы; блокеров в ключе 5). Для документов, которых агент не видел, ключи написали отдельные ИИ-помощники; сами документы лежат в `eval/blind/`, `eval/blind2/`, `eval/blind3/` (по четыре документа, у каждой папки файл `SHA256.txt`), ключи — рядом с документами (`*.key.json`).
- Скрипты: `eval/score.py` (оценка одного результата), `eval/run_all.py` (прогон по всем документам), `eval/summarize.py` (сводная таблица), `eval/check_keys.py` (проверка ключей), `eval/check_same_findings.py`, `eval/noise_by_stage.py`; сохранённые результаты — `eval/results/`.

## 6. Бизнес-ценность

Источники: `docs/VALUE.md`, `docs/PILOT.md`, `README.md` (раздел «Ценность для банка»). Расчёты повторяет `tools/roi.py`; курс 458,28 ₸ за доллар на 25.11.2026 (официальный курс Национального банка РК, `docs/VALUE.md`).

| Режим (документ организаторов, около 1 000 слов) | Цена прогона | В минутах аналитика | Порог окупаемости на документ | Доля ручной проверки |
| :--- | :--- | :--- | :--- | :--- |
| Sonnet (по умолчанию), версия 1.4.0 | $1,27 = 582 ₸ | 17 мин | 37 мин | 61,4 % |
| Haiku, прежняя версия, тег v1.1.1 | $0,18 = 85 ₸ | 2,4 мин | 22 мин | 37,4 % |
| Opus, версия 1.2.0 | $3,23 = 1 479 ₸ | 43 мин | 1 ч 3 мин | 104,6 % |
| Без модели | 0 | 0 | 20 мин | 33 % |

- Формула: порог (мин) = цена прогона в ₸ ÷ ставка в ₸/ч × 60 + минуты на чтение отчёта. Параметры по умолчанию: 3 проверяющих, темп 15 страниц в час, 5 страниц в документе, ставка 2 075 ₸ в час (340 278 ₸ в месяц ÷ 164 часа; медиана вакансий системного аналитика на hh.kz за 2025 год), 20 минут на чтение отчёта (допущение, не замер). Ручная проверка этого документа при них — 1 час (3 × 5 ÷ 15 × 60 = 60 минут).
- Пересчёт для Sonnet: 1,27 × 458,28 = 582 ₸; 582 ÷ 2 075 × 60 = 16,8 мин ≈ 17 мин; 17 + 20 = 37 мин; 37 ÷ 60 = 61,4 % (`docs/VALUE.md`).
- Сколько ручной работы агент убирает на самом деле, измеряет пилот; экономия в часах в `docs/VALUE.md` не заявлена, показаны только сценарии 10 %, 25 % и 50 % калькулятора.

**Пилот на две недели** (`docs/PILOT.md`; все пороги — предложение, утверждает банк):

- Неделя 0: подготовка, 1–2 дня (место запуска, разрешённая модель, маскирование, бюджет, ключи, пороги).
- Неделя 1: 10–12 прошлых документов; аналитики сверяют замечания агента с ревью людей и с дефектами, найденными в разработке.
- Неделя 2: 4–6 новых документов идут через ревью по очереди, с агентом и без, с учётом часов.
- Предлагаемые пороги успеха: совпадение с ревью людей не меньше 40 %; доля лишних замечаний не больше 30 %; новые верные замечания в среднем не меньше одного на два документа; измеренная экономия не меньше порога окупаемости; круги уточнений и открытые вопросы не больше, чем без агента.
- Объём: около 14–18 документов, порядка 25–40 прогонов; людей — при верхних оценках около 70–80 человеко-часов за две недели (без самого ревью недели 2).

**Встраивание** (`docs/INTEGRATION.md`): самопроверка аналитика до ревью; ворота в CI (`--fail-on`); замечания в Jira (`*.jira.csv`); отчёт в Confluence; две петли с автором (ответы на вопросы; повторная проверка после правок, `--baseline`).

## 7. Данные и безопасность

Источники: `docs/ARCHITECTURE.md` (раздел «Границы доверия»), `docs/USAGE.md` (раздел «Защита данных»), `revizor/privacy.py`, `revizor/llm/base.py`.

| Провайдер | Что уходит с компьютера |
| :--- | :--- |
| `offline` | ничего; сеть не используется |
| `ollama` и любой локальный OpenAI-совместимый сервер на этом компьютере или внутри контура | запросы идут на указанный адрес (`OLLAMA_BASE_URL`, `OPENAI_BASE_URL`); при локальном сервере документ остаётся на компьютере |
| `anthropic`, `gemini`, `openai` (облако) | текст запроса: правила, документ после маскирования, файлы `--context` после маскирования; ключ идёт провайдеру |

- Маскирование идёт в загрузчике до любой обработки и не отключается. Маскируются номера карт (13–19 цифр, проверка Луна), ИИН/БИН (12 цифр, контрольная цифра), почта (часть до «@», кроме первого символа; домен остаётся), телефоны в явной записи. Имена, почтовые адреса и номера счетов не маскируются (`docs/ARCHITECTURE.md`, `docs/PILOT.md`).
- У модели нет инструментов: она не читает файлы и не выходит в сеть. Всё, что вернула модель, проходит проверку схемы; цитаты сверяются с документом; уровни и ссылки на номера проверяются программой.
- Секреты: ключи читаются только из переменных окружения и из `.env` (`revizor/config.py`; настоящие переменные окружения главнее `.env`; `REVIZOR_NO_DOTENV=1` отключает чтение файла). `.env` перечислен в `.gitignore`; в `.env.example` только заглушки. Значения не печатаются (`revizor/config.py`). Ключи регистрируются и вырезаются из текстов ошибок, заметок и журнала функцией `redact` (`revizor/llm/base.py`: `register_secret`, `redact`; она же маскирует строки вида `api_key=…`, `x-goog-api-key`, `token`). Ключ Gemini передаётся заголовком `x-goog-api-key`, а не в адресе (`revizor/llm/gemini_backend.py`).
- Ключ, вставленный в окно (`--ui`), хранится только в памяти окна до его закрытия и никуда не записывается (`README.md`). Окно слушает только `127.0.0.1` (`revizor/webui.py`).
- Журнал решений `audit` в JSON хранит хэши запросов и ответов, токены, время и решения программы; текста документа в нём нет.
- Кэш `.cache/llm/` на машине запуска хранит ответы модели, в них есть цитаты из документа; папка в `.gitignore`.
- Запись файлов идёт через временный файл и замену, поэтому прерванный запуск не оставляет половину файла (`revizor/cli.py`: `_write_atomic`).
