# Справочник: запуск, параметры, отчёт

Короткая версия — в [README](../README.md). Здесь всё, что нужно при настройке и при чтении отчёта.

## Что лежит рядом с отчётом

Все файлы получают имя из `--output`. Всего файлов до одиннадцати, включая сам отчёт. Для `--output reports/report.md`:

| Файл | Что внутри | Когда появляется |
| :--- | :--- | :--- |
| `report.md` | отчёт для людей: первый экран, 8 разделов, приложение; каждое замечание один раз, в короткой форме | всегда |
| `report.details.md` | подробности: полные карточки с цитатами и ходом перепроверки, разбор по каждому требованию, карта полноты, вопросы автору с вариантами | если документ прочитан и главный файл — Markdown |
| `report.html` | отчёт и подробности одной страницей для браузера: открывается без интернета, печатается в PDF | всегда |
| `report.pdf` | агент его не пишет; в репозитории лежит PDF сдаваемого отчёта, напечатанный из `report.html` (в браузере: «Печать» → «Сохранить как PDF») | только в `reports/` репозитория |
| `report.summary.md` | одна страница для руководителя: вердикт, блокеры, первые вопросы | если документ прочитан |
| `report.json` | то же в машинном виде: для `--baseline`, `eval/score.py`, CI | всегда |
| `report.questions.md` | анкета автору ТЗ: вопрос, цитата, варианты ответа, строка `Ответ:` | если есть вопросы |
| `report.tests.md` | черновики приёмочных тестов «Дано / Когда / Тогда» | если есть что проверять |
| `report.fixed.md` | предложенные формулировки и список правок, которые агент не стал печатать, с причиной | с моделью или с ответами автора |
| `report.findings.csv` | замечания таблицей, по строке на замечание | если есть замечания |
| `report.jira.csv` | те же замечания в столбцах для импорта в Jira (Summary, Description, Priority, Labels, Issue Type) | если есть замечания |
| `report.diagnostic.md` | что произошло в прогоне: какие шаги модели не ответили, что отброшено и почему | если документ прочитан |

## Что в отчёте

| Часть | Содержание |
| :--- | :--- |
| Первый экран | вердикт; счётчики «блокеров · существенных · мелких»; список блокеров с основанием и строками; пять первых вопросов автору (у вопроса, который снимает блокер, это написано); что исправить в первую очередь; время и цена прогона. Если часть шагов модели не ответила, здесь же сказано, сколько и что сделать |
| 1. Паспорт прогона | документ и его SHA-256, дата, модель (и её настоящая версия, если провайдер её сообщил), версия агента (тег, коммит), режим, время, запросы и токены, стоимость, итоги проверки цитат и перепроверки, предупреждения |
| 2. Нарезка | таблица «ID в отчёте и ID в документе — тип — формулировка (цитата, длинная обрезана) — строка»; номера `REQ-001…` выдаёт программа; список блоков, не признанных требованиями, с причиной |
| 3. Каждое требование | матрица «требование × критерий»; замечания к отдельным требованиям: блокеры — полной карточкой, существенные — коротко (место, первая цитата, как исправить), мелкие — таблицей. Разбор по каждому требованию — в `*.details.md`, часть А |
| 4. Набор целиком | полнота, непротиворечивость, реализуемость и стандарты, понятность, прослеживаемость; замечания в тех же трёх формах, что в разделе 3; «Карта полноты» — итог по 35 контрольным вопросам (ответ на каждый — в `*.details.md`, часть В); «наблюдения» слабых правил; ответы на чек-лист ревью из самого документа, если он там есть |
| 5. Сводка | счётчики, замечания по критериям, индекс готовности и его формула |
| 6. Итог | вердикт, причина, что исправить первым, что в документе уже хорошо |
| 7. Вопросы автору | таблица: вопрос, кому, приоритет, к каким замечаниям; варианты ответа и «что изменит ответ» — в анкете `*.questions.md` и в `*.details.md`, часть Г |
| 8. Черновики тестов | таблица; полные тексты — в `*.tests.md` |
| Приложение | метод, что отклонила перепроверка, ограничения прогона |

Если `--output` оканчивается на `.json`, главным файлом будет JSON, а Markdown-отчёт и файл подробностей `.details.md` не пишутся. Если на `.html`, агент пишет Markdown с тем же именем и `.md` и говорит об этом; страница `.html` при этом всё равно появляется рядом, как при любом запуске.

Если файл нельзя прочитать (скан без текста, битый PDF, пустой файл), агент пишет отчёт «Документ не проверен» с причиной и шагами: `.md`, `.json` и `.html`. Примеры — `reports/diagnostics/`. Так же он поступает, если файла по указанному пути нет или вместо файла указана папка. Код возврата при этом 0, а с `--fail-on critical` или `major` — 4.

### Уровни замечаний

| Уровень | Что значит |
| :--- | :--- |
| 🔴 CRITICAL | блокер, только по одному из пяти оснований: противоречие в документе; не определён основной сценарий; нарушение стандарта протокола; прямая потеря денег, данных или доступа; нет обязательной части документа. Основание печатается в карточке |
| 🟡 MAJOR | разработчик и тестировщик сделают или проверят разное: пропущен сценарий ошибки, термин меняет результат, расходятся форматы, критерий нельзя проверить |
| 🟢 MINOR | то, что грамотная команда решит одинаково без вопросов: редкий крайний случай, стиль, термины, нет номера или версии |

Если модель ставит CRITICAL и не называет основание, программа понижает замечание до MAJOR. Паспорт показывает, сколько было таких понижений.

**Вердикт** считает программа. Есть открытый CRITICAL — «начинать нельзя». Нет CRITICAL, есть MAJOR — «после ответов на вопросы и исправления существенных замечаний». Иначе — «можно начинать». Без модели вердикт помечается предварительным.

**Индексы** (формулы в `revizor/score.py`):

- Ясность требования, от 1 до 10: `10 − сумма весов` замечаний к нему. Вес CRITICAL 6,5, MAJOR 2,5, MINOR 0,75. Замечания к набору, где требование названо, идут с половинным весом.
- Готовность документа, от 0 до 100: `10 × средняя ясность − штраф` за замечания к набору (`8·C + 3·M + 1·m`, не больше 40).
- Полосы: 85 и выше — готов; 60–84 — готов после правок; 40–59 — нужна существенная доработка; ниже 40 — не готов.

Индекс показывает объём работы. Вердикт определяют только блокеры. Индекс зависит от режима: без модели проверяются только формальные правила, замечаний меньше и индекс выше (на документе организаторов 54 без модели против 23 с Opus). Сравнивать индексы можно только внутри одного режима.

## Диалог с автором ТЗ

Агент пишет анкету `<отчёт>.questions.md`. Автор вписывает ответы (буквой варианта или своими словами) и запускает проверку с ними. Команда напечатана в конце анкеты. Отчёт с ответами она пишет рядом с первым, добавляя к имени `_answered` (`reports/report.md` → `reports/report_answered.md`), так что первый отчёт не затирается. В папке `reports/` под такими именами уже лежат образцы; чтобы не затереть их, укажите своё имя:

```bash
python main.py --input docs/requirements.md --output reports/my_answered.md --answers reports/sample_answers.md
```

С моделью агент разбирает ответы, отмечает закрытые замечания, предлагает новые формулировки и показывает два вердикта: по документу как есть и после внесения ответов. Первый проход при этом берётся из кэша, к модели идёт в основном разбор ответов.

Без модели ответ записывается рядом с вопросом. Выбранный вариант («а», «б», «в») закрывает замечание, если вопрос составлен по шаблону этого замечания. Ответ своими словами только записывается: замечание остаётся открытым, решать его будет человек или прогон с моделью.

Внутри каждой группы (блокирующие, важные, желательные) вопросы стоят по влиянию: сначала те, что закрывают больше блокеров, затем те, что сильнее поднимают индекс готовности.

Вопросы можно задать и в терминале, до 7 штук, сначала блокирующие: добавьте `--interactive`.

### Подробно: ответы автора и повторная проверка

Автор вписывает ответы буквой варианта или своими словами и запускает проверку с анкетой:

```bash
python main.py --input docs/requirements.md --output reports/my_report_answered.md --answers reports/my_report.questions.md
```

Что меняется после ответов:

- **С моделью** агент разбирает каждый ответ, отмечает закрытые замечания и показывает два вердикта: по документу как есть и после внесения ответов. Новые формулировки требований ложатся в `<отчёт>.fixed.md`. Первый проход берётся из кэша, к модели идёт в основном разбор ответов.
- **Без модели** выбранный вариант закрывает замечание, если вопрос составлен по шаблону этого замечания. Ответ своими словами записывается, а замечание остаётся открытым.
- В начале отчёта появляется строка: сколько ответов учтено и сколько замечаний закрыто.

Пример без модели: анкета [`reports/sample_answers.md`](../reports/sample_answers.md), результат [`reports/report_offline_answered.md`](../reports/report_offline_answered.md).

Вопросы можно задать и в терминале, по одному, до 7 штук, сначала блокирующие:

```bash
python main.py --input docs/requirements.md --output reports/my_report.md --interactive
```

Когда автор исправил сам документ, повторная проверка сравнивает новую версию (здесь `docs/requirements_v2.md` — файл, который пишет автор) с прошлым JSON-отчётом:

```bash
python main.py --input docs/requirements_v2.md --output reports/my_report_v2.md --baseline reports/my_report.json
```

В отчёте появится строка «С прошлой проверки»: сколько замечаний исправлено, сколько осталось, сколько новых.

## Повторная проверка после правок

```bash
python main.py --input docs/requirements_v2.md --output reports/report_v2.md --baseline reports/report.json
```

В отчёте появится строка «С прошлой проверки»: сколько замечаний исправлено, сколько осталось и сколько новых.

## Дополнительные материалы

```bash
python main.py --input docs/requirements.md --output reports/my_report.md --context glossary.md --context api_spec.md
```

Глоссарий или связанная спецификация передаются модели как справка. Для модели это данные, а не указания: они стоят в запросе между своими метками, как и сам документ. Замечания пишутся только к основному документу, цитаты берутся только из него. Файлы контекста проходят то же маскирование. Файл контекста, который не удалось прочитать, пропускается с предупреждением в паспорте.

## Окно в браузере

```bash
python main.py --ui
```

Команда запускает маленький сервер на этом компьютере и открывает страницу `http://127.0.0.1:8765/`. На странице: выбор документа (те же форматы, что у `--input`), необязательный файл с ответами автора, модель, глубина, потолок расходов, оценка времени и цены до запуска (те же числа, что печатает `--estimate`) и кнопка «Проверить». Пока идёт проверка, видны девять этапов, число запросов к модели, число ответов из кэша и расход. В конце — вердикт, индекс готовности, счётчики замечаний и ссылки на все файлы отчёта. Светлая и тёмная тема.

| Параметр | Значение при `--ui` |
| :--- | :--- |
| `--ui` | открыть окно |
| `--port N` | номер порта (по умолчанию 8765); если порт занят, агент скажет об этом и попросит указать другой |
| `--no-browser` | не открывать браузер самому, только напечатать адрес |
| `--input FILE` | документ, который сразу выбран в окне (необязательно) |
| `--output DIR` | папка для отчётов (по умолчанию `reports/ui`) |
| `--model`, `--depth`, `--max-cost` | что выбрано в окне сразу; на странице это можно поменять |
| `--provider`, `--no-cache` | действуют на каждую проверку из окна |

- **Тот же код.** Проверку из окна делает та же функция, что и из терминала: те же этапы, тот же кэш, тот же потолок расходов, те же файлы. Второй логики нет.
- **Куда пишется отчёт.** В `<папка>/<имя документа>.md`, остальные файлы — рядом. Проверка с ответами автора пишется в `<имя документа>_answered.md` и первый отчёт не затирает. Два разных документа с одинаковым именем пишутся в одни и те же файлы: второй заменит первый.
- **Одна проверка за раз.** Кнопки «Отменить» нет: чтобы прервать проверку, остановите сервер (`Ctrl+C`). Потолок расходов защищает от лишних трат и здесь.
- **Оценка считается без кэша.** Если документ уже проверяли этой моделью, проверка пройдёт быстрее и бесплатно, а страница покажет, сколько ответов взято из кэша.
- **Только этот компьютер.** Сервер слушает адрес `127.0.0.1`. Запросы с чужих страниц он отклоняет: сверяет заголовки `Host` и `Origin` и требует свой заголовок у каждого запроса на запись. Выбранный файл копируется во временную папку и удаляется при остановке. Сервер отдаёт только файлы отчёта своей проверки, по списку, а не по пути из запроса. Ключи на страницу и в журнал сервера не попадают.
- **Без интернета.** Страница — один файл без внешних шрифтов, скриптов и картинок. Наружу уходят только запросы к модели, те же, что из терминала.

Код: `revizor/webui.py` (сервер, только стандартная библиотека Python) и `revizor/webui_page.html` (страница).

## Windows и Linux

Нужен Python 3.10 или новее. Агент разрабатывался и проверялся на macOS. Работу в консоли Windows проверяют тесты переносимости (`tests/test_portability.py`): настоящий запуск под кодировками cp866, cp1251 и ASCII, документ с BOM и переводами строк CRLF, пути с пробелами и кириллицей, имена файлов, допустимые в Windows. Исходный код собирается на Python 3.9–3.15. Для прогона всех тестов на Ubuntu, Windows и macOS с Python 3.10, 3.12 и 3.13 приложен сценарий GitHub Actions `.github/workflows/tests.yml` (запускается вручную: Actions → tests → Run workflow).

**Windows, командная строка (cmd):**

```bat
py -m venv .venv
.venv\Scripts\activate.bat
pip install -r requirements.txt
python main.py --input docs\requirements.md --output reports\my_report.md
python main.py --ui
```

**Windows, PowerShell:**

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1      # если запрещено: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
pip install -r requirements.txt
python main.py --input docs/requirements.md --output reports/my_report.md
python main.py --ui
```

Пути можно писать и через `\`, и через `/`; путь с пробелами берите в кавычки: `--output "C:\Отчёты ТЗ\отчёт.md"`. Кодовую страницу консоли менять не нужно: символ, которого в ней нет (например, ⛔ в cp866), печатается как `?`, а в файлы отчёта всё пишется в UTF-8. Окно `--ui` открывается в браузере по умолчанию и закрывается `Ctrl+C` в консоли.

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py --input docs/requirements.md --output reports/my_report.md
```

На сервере без графики (`DISPLAY` не задан) `--ui` не пытается открыть браузер сам, а печатает адрес. Окно слушает только `127.0.0.1`; с другой машины его можно открыть через SSH-туннель: `ssh -L 8765:127.0.0.1:8765 сервер`.

## Все параметры запуска

| Параметр | Значение |
| :--- | :--- |
| `--input`, `-i` | документ: `.md`, `.txt`, `.pdf`, `.docx`, `.html` |
| `--output`, `-o` | куда записать отчёт (`.md`); остальные файлы лягут рядом |
| `paths` | то же без ключей: `python main.py <документ> <отчёт.md>` |
| `--provider` | `auto` (по умолчанию), `anthropic`, `gemini`, `openai`, `ollama`, `offline` |
| `--model` | имя модели (иначе из `.env` или встроенное) |
| `--depth` | `full` (по умолчанию: три линзы и перепроверка) или `fast` (один проход, меньше запросов) |
| `--context FILE` | дополнительные материалы; можно несколько раз |
| `--answers FILE` | анкета с ответами автора |
| `--interactive` | задать до 7 вопросов в терминале |
| `--baseline OLD.json` | сравнить с прошлым JSON-отчётом |
| `--no-cache` | не брать ответы модели из кэша (запись в кэш остаётся) |
| `--fail-on` | `never` (по умолчанию), `critical`, `major` — для CI, см. коды возврата |
| `--max-cost USD` | потолок стоимости в долларах: перед каждым запросом агент сравнивает потраченное с потолком; после потолка модель не вызывается, остальное делают правила и шаблоны |
| `--focus` | режим «только главное»: мелкие замечания, которые перепроверка отнесла ко второму плану, уходят из основного списка в раздел «Наблюдения» с причиной под каждым. По умолчанию выключен: в основном списке остаются все замечания |
| `--estimate` | только оценить число запросов, токены и цену; модель не вызывается |
| `--quiet`, `-q` | печатать только итог |
| `--ui`, `--port N`, `--no-browser` | окно в браузере вместо терминала, см. [«Окно в браузере»](#окно-в-браузере) |
| `--version` | напечатать версию и выйти |

**Коды возврата** (`revizor/cli.py`):

| Код | Когда |
| :--- | :--- |
| `0` | отчёт записан, порог `--fail-on` не достигнут. Сюда же: диагностический отчёт при `--fail-on never`, `--estimate`, `--help`, `--version` |
| `1` | неверные параметры (агент печатает «Ошибка в параметрах…»), отчёт записать не удалось или запуск прерван |
| `3` | есть открытые замечания уровня из `--fail-on` (`critical` или `major`); отчёт записан |
| `4` | задан `--fail-on critical` или `major`, а документ прочитать не удалось; диагностический отчёт записан. Так нечитаемый файл не пройдёт ворота незамеченным |

Кода `2` нет: ошибки разбора параметров агент перехватывает и возвращает `1`.

**Кэш.** Ответы модели сохраняются в `.cache/llm/`. Ключ — провайдер, модель, усилие и текст запроса. Повторный запуск по тому же документу и той же модели не тратит деньги и запросы заново. Если часть шагов не ответила, второй запуск повторит только их. `--no-cache` не читает кэш, но пишет в него свежие ответы.

**Потолок расхода.** Если `--max-cost` достигнут, следующие шаги модели не выполняются: перепроверка пропускается, вопросы строятся по шаблонам правил, тесты — только программные, чек-лист из документа остаётся без ответов. Паспорт отчёта пишет об этом в списке «Предупреждения», например «Достигнут лимит стоимости $3.5: дальше модель не вызывалась, оставшиеся этапы выполнены без неё». Если цена модели неизвестна, потолок применить нельзя, и паспорт об этом предупреждает.

## Выбор модели

Провайдер выбирается по порядку: `LLM_PROVIDER` → `ANTHROPIC_API_KEY` → `GEMINI_API_KEY` (или `GOOGLE_API_KEY`) → `OPENAI_API_KEY` → `OLLAMA_BASE_URL` → без модели. Первая строка вывода называет выбранный режим, например «Режим: без модели — только автоматические правила». Значения-заглушки вроде `your-…-here` считаются отсутствующими.

| Переменная | Назначение |
| :--- | :--- |
| `LLM_PROVIDER` | `auto`, `anthropic`, `gemini`, `openai`, `ollama`, `offline` |
| `GEMINI_API_KEY` (или `GOOGLE_API_KEY`), `GEMINI_MODEL` | Gemini; модель по умолчанию `gemini-flash-latest`. Устаревшее имя (например `gemini-1.5-flash` из образца организаторов) агент сам заменит на действующее |
| `GEMINI_FALLBACK_MODEL` | запасная модель Gemini на случай перегрузки основной; по умолчанию `gemini-flash-lite-latest`; пусто или `off` — выключить |
| `GEMINI_OVERLOAD_WAIT_S` | сколько секунд за прогон можно ждать перегруженный Gemini; по умолчанию 600; `0` — не ждать. В первом круге один шаг тратит не больше шестой части остатка, повтор неотвеченных шагов может взять остальное |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | Anthropic; модель по умолчанию `claude-haiku-5-5` |
| `ANTHROPIC_EFFORT`, `ANTHROPIC_EFFORT_STAGES` | глубина рассуждений: одна для всех этапов или по этапам; см. ниже |
| `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_BASE_URL` | OpenAI или совместимый сервер |
| `OLLAMA_BASE_URL`, `OLLAMA_MODEL` | локальная модель, ключ не нужен |
| `LLM_ECONOMY` | режим экономии запросов: самые ценные шаги первыми (противоречия, критик, линзы, затем полнота и стандарты), нарезка без модели, шаги без ответа из-за перегрузки повторяются один раз. `auto` (по умолчанию) — только для Gemini, `on` — для любого провайдера, `off` — выключен |
| `LLM_BATCH_SIZE` | сколько требований в одном запросе (1–200). По умолчанию 12, для Gemini 40: бесплатный уровень считает запросы |
| `LLM_CONCURRENCY` | сколько запросов идёт одновременно (1–32); по умолчанию 1 у Gemini и Ollama, 4 у Claude и OpenAI |
| `LLM_TIMEOUT` | сколько секунд ждать ответа на один запрос; по умолчанию 600 у Claude, 900 у Ollama, 300 у остальных |
| `LLM_MAX_TOKENS` | потолок длины ответа в токенах, рассуждения входят в него. Пусто — значения агента по этапам (проверки набора сразу получают 64 000). Число заменяет значения всех этапов и отключает повтор обрезанного ответа, поэтому ставьте не меньше 64000 |
| `REVIZOR_MAX_COST_USD` | то же, что `--max-cost` |
| `REVIZOR_FOCUS` | `1` — то же, что `--focus` |
| `REVIZOR_NO_DOTENV` | `1` — не читать `.env` |

Все переменные с пояснениями — в `.env.example`. Переменные, заданные в терминале, важнее `.env`.

### Глубина рассуждений у Claude

Рассуждения модели оплачиваются как выход и составляют основную часть цены. Поэтому усилие задано по этапам (`STAGE_EFFORT` в `revizor/llm/base.py`):

| Усилие | Этапы |
| :--- | :--- |
| `high` | поиск противоречий между разделами (`set_consistency`) |
| `medium` | остальные проверки набора (`set_completeness`, `set_standards`, проход-критик `set_gaps`), перепроверка (`skeptic`), разбор ответов автора (`answers`) |
| `low` | нарезка (`slice`), проверка требований тремя линзами (`review`), вопросы (`questions`), черновики тестов (`tests`), ответы на чек-лист из документа (`checklist`) |

`ANTHROPIC_EFFORT=medium` задаёт одно усилие для всех этапов. `ANTHROPIC_EFFORT_STAGES=review=low,set=high` меняет отдельные этапы поверх значений по умолчанию и не действует, если задан `ANTHROPIC_EFFORT`. Допустимые значения: `low`, `medium`, `high`, `xhigh`, `max`.

Если ответ обрезан по лимиту токенов, агент делает ровно один повтор с усилием на ступень ниже. Если ниже некуда или усилие у провайдера не применяется, повтор идёт с большим потолком, до 64 000. Ответ повтора пишется в кэш под исходным усилием, поэтому следующий такой же прогон берёт его из кэша. При заданном `LLM_MAX_TOKENS` повтора нет.

### Режим экономии

Нужен для бесплатных уровней, где считаются запросы в день и модель часто отвечает «перегружена». `LLM_ECONOMY=auto` (по умолчанию) включает его только для Gemini, `on` — для любого провайдера, `off` выключает.

- Нарезка на требования идёт без запроса к модели, эвристикой.
- Шаги проверки отправляются по ценности: противоречия между разделами, проход-критик, линзы «корректность», «полнота», «ясность», затем полнота и стандарты набора. Ответы модели разбираются в прежнем порядке, поэтому номера замечаний от порядка отправки не зависят.
- У Gemini запросы идут по одному: `LLM_CONCURRENCY` по умолчанию 1.
- Шаг, сорвавшийся из-за временного сбоя (перегрузка, тайм-аут, лимит в минуту), повторяется один раз во втором круге, если провайдер ещё отвечает и потолок стоимости не достигнут.
- Gemini: если основная модель перегружена (503) или кончилась её дневная квота (429), агент один раз за прогон переходит на запасную модель (`GEMINI_FALLBACK_MODEL`, по умолчанию `gemini-flash-lite-latest`) и остаётся на ней. Ждать перегруженную модель агент может до `GEMINI_OVERLOAD_WAIT_S` секунд за прогон (по умолчанию 600).

Замер на бесплатном Gemini, документ организаторов, первый прогон без кэша: 15 шагов модели, ответ на 14, 47 запросов, 7 мин 17 с, $0. У основной модели кончилась дневная квота, работу сделала запасная. Google много раз отвечал «перегружен» (503). Запросов больше, чем шагов, из-за повторов и перехода на запасную модель. Второй прогон с кэшем доделал оставшийся шаг за 4 с. Число шагов зависит от документа: от числа пакетов требований (у Gemini по 40 в пакете) и от того, есть ли в документе чек-лист ревью. `--depth fast` убирает три линзы (остаётся один проход), перепроверку и черновики тестов от модели.

**Режим экономии.** Запросы идут по одному, по ценности: противоречия в наборе, критик, линзы, полнота, стандарты. Нарезка на требования идёт без модели. Шаг, сорвавшийся из-за перегрузки или тайм-аута, повторяется один раз во втором круге. Ждать перегруженный Gemini агент может до 600 с за прогон. На документе организаторов это 15 шагов модели.

Замер на бесплатном Gemini (тег v1.1.1, первый прогон без кэша): 15 шагов модели, ответ на 14, 47 запросов, 437 с, $0. У основной модели кончилась дневная квота (ответ 429), работу сделала запасная `gemini-flash-lite-latest`. Google много раз отвечал «перегружен» (503). Три шага не получили ответа в первом круге, все три ответили во втором. Единственный шаг без ответа (чек-лист ревью из самого документа) назван в отчёте. Второй прогон с кэшем доделал его за 4 с и 2 запроса.

## Защита данных

- **Маскирование до отправки.** В загрузчике, до любой обработки, звёздочками заменяются: номера карт (13–19 цифр подряд или привычными группами, проходящие проверку Луна, кроме одинаковых цифр), ИИН/БИН (12 цифр, по контрольной цифре), адреса почты (часть до «@», кроме первой буквы; домен остаётся) и телефоны в явной записи («+7» и десять цифр, «8» с группами 3-3-2-2, «+» и 10–14 цифр). Имена, почтовые адреса и номера счетов не маскируются. Длина текста не меняется, номера строк остаются верными. Паспорт показывает, сколько значений скрыто. Отключить маскирование нельзя.
- **Текст документа — данные, а не указания.** В запросе документ стоит между метками `<document-XXXXXXXX>`, где `XXXXXXXX` — первые 8 знаков SHA-256 самого документа; автор документа не может знать метку заранее. Файлы `--context` стоят между такими же метками `<context-XXXXXXXX>`. Служебные теги внутри текста (`<document…`, `</document…`, `<context…`) обезвреживаются: первая «<» заменяется похожим знаком, и текст не может закрыть метку. Правила `prompt-injection` и `hidden-text` находят обращения к проверяющему или к ИИ и скрытый текст и показывают их как дефекты. Модель не может отклонить находку правила.
- **У модели нет инструментов.** Запрос — только текст и схема ответа.
- **Ключи.** Только в `.env` (он в `.gitignore`) или в переменных окружения. Ключ Gemini передаётся заголовком, а не в адресе. Ключи вырезаются из текстов ошибок, заметок и журнала.
- **Журнал решений.** В JSON-отчёте поле `audit` хранит хэши запросов и ответов, токены, время и решения программы. Текста документа там нет.
- **Кэш на диске.** Ответы модели лежат в `.cache/llm/` на машине запуска. В них есть цитаты из документа: доступ к папке стоит ограничить.

## На что опирается проверка

Критерии взяты из ISO/IEC/IEEE 29148:2018 и IEEE 830-1998. У каждого замечания в карточке есть строка «Основание» с пунктом стандарта (таблица в `revizor/merge.py`).

Каждое требование проверяется по семи критериям (29148 п. 5.2.5; IEEE 830 п. 4.3):

| Критерий | Основание |
| :--- | :--- |
| Полнота | 29148 п. 5.2.5 (Complete), IEEE 830 п. 4.3.3 |
| Однозначность | 29148 п. 5.2.5 (Unambiguous), IEEE 830 п. 4.3.2 |
| Непротиворечивость | IEEE 830 п. 4.3.4 |
| Проверяемость | 29148 п. 5.2.5 (Verifiable), IEEE 830 п. 4.3.6 |
| Реализуемость | 29148 п. 5.2.5 (Feasible) |
| Необходимость | 29148 п. 5.2.5 (Necessary, Appropriate) |
| Атомарность | 29148 п. 5.2.5 (Singular) |

Набор целиком проверяется по пяти критериям (29148 п. 5.2.6; IEEE 830 п. 4.3):

| Критерий | Основание |
| :--- | :--- |
| Полнота набора | 29148 п. 5.2.6 (Complete), IEEE 830 п. 4.3.3 |
| Взаимная непротиворечивость | 29148 п. 5.2.6 (Consistent), IEEE 830 п. 4.3.4 |
| Реализуемость, стандарты и безопасность | 29148 п. 5.2.6 (Feasible) |
| Понятность и термины | 29148 п. 5.2.6 (Comprehensible) |
| Прослеживаемость | IEEE 830 п. 4.3.8 (Traceable) |

Правил без модели 27 основных и 8 слабых «наблюдений» (`revizor/rules/`). Наблюдения не входят в индексы и вердикт. Проход-критик отвечает на 35 контрольных вопросов в восьми группах (`revizor/gapcheck.py`).

## Ограничения

- **Отчёт всё ещё длинный.** Основной отчёт — около 8,7 тысячи слов на документ в 1–1,4 тысячи слов (как считать знаки таблиц): в 6–9 раз длиннее самого документа. До тега `v1.1.2` было 17 тысяч, у версии `v1.0.0` — 23 тысячи. Полные карточки вынесены в файл `*.details.md` (ещё 12,6 тысячи слов); читать его подряд не нужно, туда ведут ссылки «подробно». Начинать стоит с первого экрана и с [`reports/report.summary.md`](../reports/report.summary.md) (одна страница).
- **Индекс готовности зависит от режима.** Без модели проверяются только формальные правила, замечаний меньше и индекс выше: на документе организаторов 54 без модели против 23 с Opus. Сравнивать индексы можно только внутри одного режима; вердикт от индекса не зависит.
- **На незнакомых документах много шума.** По оценке судьи, ложное каждое четвёртое замечание у Haiku и каждое шестое у Opus. Хуже всего почти чистый документ: на 5 дефектов ключа агент написал 64–70 замечаний, от трети до почти половины — ложные.
- **Агент завышает уровни.** На четырёх новых документах он отметил как блокеры 18 замечаний (Haiku) и 21 (Opus), а в ключах блокеров 9.
- **«Описано» в карте полноты не значит «раскрыто полностью».** Отметку ставит модель и подкрепляет строкой документа: тема в документе затронута. В сданном отчёте так отмечены «изменения задним числом» (строка 38: возврат уменьшает расходы месяца покупки) и «несколько однотипных объектов» (строка 39: один push на карту в месяц). Образец организаторов спрашивает по этим темам глубже: что делать с уже отправленным push после возврата и задаётся ли порог на карту или на клиента. Отдельных вопросов об этом в отчёте нет — это пропуск агента.
- **Потолок расхода может оборвать прогон.** На Opus два новых документа дошли до `--max-cost`. В одном из них перепроверка была пропущена целиком. Отчёт пишет об этом в паспорте прогона, в списке предупреждений.
- **Бесплатный Gemini медленный.** Дневная квота и перегрузка на стороне Google: прогон может занять 7 минут и оставить шаг без ответа. Отчёт называет такой шаг, второй прогон его доделывает.
- **Числа точности — по одному прогону на число.** Ключи дефектов писала команда. Независимый судья — ИИ-модель в отдельной сессии, а не человек.
- **Экономия времени рассчитана** по опубликованным темпам ревью, а не измерена на живом аналитике.
- **Сканы PDF без текстового слоя не читаются:** OCR нет, агент пишет диагностический отчёт с советом. Картинки и схемы-рисунки тоже не читаются. Старый формат `.doc` не поддерживается. Предел — 400 000 знаков.
- **Без модели** ищутся только формальные дефекты. Смысловые противоречия и пропущенные сценарии ищет модель.
- **Внутренних стандартов банка агент не знает,** пока их не передать через `--context`.
- **OpenAI-совместимые серверы и Ollama** проверены только тестами с заглушкой вместо сервера. Живьём агент работал на Anthropic и Gemini.
- **Python.** Живьём агент запускался только на Python 3.15. На версиях 3.10–3.14 он не запускался.
- **Агент — первый проход.** Чистый отчёт не значит, что документ готов. Решение «готово к разработке» остаётся за человеком.

### Чтение документов и прочее

- **PDF:** таблицы и списки теряют разметку, номера строк считаются по извлечённому тексту. Правила для таблиц на PDF могут не сработать. Паспорт об этом предупреждает.
- **Сканы PDF без текстового слоя не читаются.** OCR нет: агент пишет отчёт «Документ не проверен» и советует распознать скан.
- **Старый формат Word `.doc` не читается.** Нужно сохранить файл как `.docx`.
- **Рисунки и схемы-картинки не проверяются,** учитывается только текст.
- **Предел размера — 400 000 знаков.** Больший документ получает отчёт «Документ не проверен».
- **Правила без модели настроены на русский и английский.**
- **Внутренних стандартов банка агент не знает,** пока их не передать через `--context`.
- **Без модели** ищутся только формальные дефекты, вердикт помечен предварительным.
- **Слабые места, измеренные на контрольных документах:** агент ставит лишние блокеры (на четырёх новых документах 18 у Haiku и 21 у Opus при 9 в ключах), заметная доля замечаний — ложные тревоги, отчёт длинный (основной файл — около 8,7 тысячи слов на документ организаторов, ещё 12,6 тысячи в файле подробностей). Числа точности и метод — в [`eval/ACCURACY.md`](../eval/ACCURACY.md).
- **Версия в паспорте.** Паспорт печатает строку версии пакета (сейчас «v1.3.0»; в отчётах, собранных раньше, — «v1.0.0») рядом с тегом git. Точная версия — тег и коммит.
