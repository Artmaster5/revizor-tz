# Сайт для пробы на Render.com

Сайт — это то же окно, что `python main.py --ui`, но для чужих людей: `python main.py --public`. Код — `revizor/public.py`, тесты — `tests/test_public.py`. Сборка — `Dockerfile`, настройки Render — `render.yaml` в корне репозитория.

## Как выложить (≈10 минут, бесплатно)

1. Ветка с сайтом должна быть в репозитории на GitHub (например, слита в `main`).
2. Получите бесплатный ключ Gemini: [aistudio.google.com](https://aistudio.google.com) → **Get API key** → **Create API key**. Ключ никуда не вставляйте, кроме панели Render на шаге 5.
3. Откройте [dashboard.render.com](https://dashboard.render.com) и войдите через GitHub.
4. **New** → **Blueprint** → выберите репозиторий → ветку (`main`) → Render прочитает `render.yaml` и покажет сервис `revizor-tz` (Docker, тариф Free).
5. Render попросит значение `GEMINI_API_KEY`: вставьте ключ из шага 2. Остальные переменные уже заполнены (таблица ниже).
6. Нажмите **Deploy Blueprint** (или **Apply**). Сборка занимает 3–5 минут. В журнале в конце появится строка «Сайт открыт: …».
7. Откройте адрес сервиса вида `https://revizor-tz.onrender.com` (точное имя — вверху страницы сервиса). Проверка: `https://<адрес>/healthz` отвечает `ok`, `https://<адрес>/example` сразу показывает готовый отчёт.
8. Впишите этот адрес в `README.md` (у нас — https://revizor-tz.onrender.com).

Бесплатный сервер засыпает после 15 минут без посетителей. Первое открытие после сна занимает до минуты, дальше страница отвечает сразу. Перед показом жюри откройте сайт заранее.

Команда запуска внутри контейнера: `python main.py --public` (порт берётся из `$PORT`, Render задаёт его сам; адрес `0.0.0.0`).

## Переменные окружения

Менять можно в панели Render: сервис → **Environment**. После сохранения сервис перезапускается сам, новая сборка не нужна.

| Переменная | Что значит | По умолчанию |
| :--- | :--- | :--- |
| `GEMINI_API_KEY` | ключ сервера (бесплатный Gemini); без него проверки идут по правилам, без модели | нет |
| `GEMINI_MODEL` | модель Gemini | `gemini-flash-latest` (при исчерпанной квоте агент сам переходит на `gemini-flash-lite-latest`) |
| `ACCESS_CODE` | если задан, модель сервера работает только с этим кодом (поле «Код доступа» на странице); без кода можно проверить правилами или со своим ключом. Добавляется вручную | пусто |
| `PUBLIC_RUNS_PER_IP` | проверок с моделью сервера с одного адреса в день (перепроверка с ответами тоже считается) | 3 |
| `PUBLIC_DAILY_RUNS` | проверок с моделью сервера на всех в день | 20 |
| `PUBLIC_CHECKS_PER_IP` | всех проверок с одного адреса в день: с моделью, своим ключом и без модели | 20 |
| `PUBLIC_UPLOADS_PER_IP` | загрузок файлов с одного адреса в день | 40 |
| `PUBLIC_MAX_UPLOAD_MB` | размер документа, МБ | 5 |
| `PUBLIC_RUN_TIMEOUT_S` | время на одну проверку, с; после него модель больше не вызывается, проверка заканчивается тем, что есть | 900 |
| `PUBLIC_JOB_TTL_MIN` | сколько минут хранится закончившаяся проверка | 120 |
| `PUBLIC_TRUST_PROXY` | откуда брать адрес посетителя: `first` — первая запись `X-Forwarded-For` (так в `render.yaml`), `0` — адрес соединения (сайт без прокси), `N` — N-я запись справа | 0 |
| `PUBLIC_PROVIDER` | провайдер ключа сервера: `gemini`, `anthropic` или `openai` (ключ — в его переменной) | `gemini` |
| `PORT`, `PUBLIC_HOST` | порт и адрес | `$PORT` от Render, `0.0.0.0` |

Сутки считаются по времени Алматы. Счётчики живут в памяти: после перезапуска или сна сервера день начинается заново, а дневной лимит Google на бесплатном ключе остаётся главным ограничителем.

## Как устроена защита

- **Каждая проверка отдельно.** Загрузка и проверка получают случайный номер из 32 шестнадцатеричных знаков и свою временную папку. Страница, статус, вопросы, ответы и файлы отчёта доступны только по этому номеру; «последней проверки» на сайте нет. Файлы отдаются только из списка, который записала сама проверка, поэтому обход путей (`../`) не работает. Закончившиеся проверки удаляются через `PUBLIC_JOB_TTL_MIN`.
- **Свой ключ посетителя.** Ключ приходит в теле запроса вместе с одной проверкой (в адресе не принимается), хранится в памяти до её конца, вырезается из всех текстов ошибок и журнала, на диск не пишется и в ответах не возвращается. Ключи и адреса сервера в такую проверку не передаются. Ключ уходит только на официальные адреса Anthropic, Google и OpenAI; локальный провайдер `ollama` на сайте недоступен.
- **Ключ сервера** не виден посетителю и тратится только в пределах лимитов. Одновременно идёт одна проверка с моделью; второй посетитель видит «попробуйте через минуту». Проверка без модели может идти рядом.
- **Журнал сервера**: метод, путь (номер проверки обрезан до 6 знаков) и код ответа; ни ключей, ни имён файлов, ни адресов посетителей.
- **Заголовки**: Content-Security-Policy (страница без внешних ресурсов; отчёт в песочнице), `X-Frame-Options: DENY`, `Strict-Transport-Security`, `nosniff`, `no-store`. POST-запросы принимаются только со страницы сайта (заголовок `X-Revizor-UI` и проверка `Origin`).
- **Образ**: `python:3.12-slim`, ставится только `requirements.txt`, процесс работает не от root; `.env`, `.git`, кэш и тесты в образ не попадают (`.dockerignore`), чтение `.env` выключено (`REVIZOR_NO_DOTENV=1`).

На бесплатном ключе Gemini Google может использовать присланные тексты для улучшения своих продуктов. Поэтому на сайте написано, что секретный документ лучше проверять у себя: агент работает на вашем компьютере без интернета (`--provider offline`) или с локальной моделью (`--provider ollama`).

## Проверить у себя до выкладки

```bash
REVIZOR_NO_DOTENV=1 PORT=8000 python main.py --public      # без ключа: только правила
# открыть http://127.0.0.1:8000
```

С Docker (если установлен; ключ берётся из переменной окружения терминала, в команду он не пишется):

```bash
docker build -t revizor-tz .
docker run --rm -p 10000:10000 -e GEMINI_API_KEY revizor-tz
# открыть http://127.0.0.1:10000
```
