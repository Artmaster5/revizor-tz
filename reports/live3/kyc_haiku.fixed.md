# Предлагаемые формулировки для «kyc\_upload\_api\_en.md»

Черновики исправленных требований: написанные проверяющим без решения автора и учитывающие ответы автора. Перед внесением в документ их должен прочитать автор: модель могла ошибиться.

| Требование | Было | Стало | Основание |
| :--- | :--- | :--- | :--- |
| REQ-002 | 2.1. All endpoints are served over HTTPS only, TLS 1.2 or higher; plain HTTP requests are rejected without redirect. | Если запрос пришёл по HTTP, то сервер должен отклонить его ответом 400 Bad Request без перенаправления на HTTPS и не выполнять операцию. | замечание D-002 |
| REQ-003 | 2.2. Every request carries Authorization: Bearer \<access\_token\> issued to the onboarding session. The access token lifetime is 15 minutes. | Когда запрос приходит без заголовка Authorization или с недействительным либо истёкшим токеном, сервер должен вернуть 401 Unauthorized и не выполнить операцию. | замечание D-004 |
| REQ-005 | 2.4. Every POST request must carry an Idempotency-Key header (UUID v4). A repeated request with the same key within 24 hours returns the original response and does not create a new upload. | Если POST-запрос пришёл без заголовка Idempotency-Key или значение не является UUID v4, то сервер должен ответить 400 Bad Request и не создавать загрузку. | замечание D-008 |
| REQ-007 | 2.6. The client app compresses images, strips EXIF location data, shows a progress bar and retries failed uploads up to 3 times. | Если загрузка завершилась сетевой ошибкой или кодом 5xx, клиент должен повторить запрос с тем же Idempotency-Key не более 3 раз; после третьей неудачи клиент должен показать сообщение об ошибке и предложить повторить загрузку вручную. Ошибки 4xx клиент не повторяет. | замечание D-009 |
| REQ-007 | 2.6. The client app compresses images, strips EXIF location data, shows a progress bar and retries failed uploads up to 3 times. | Когда загрузка документа завершилась сбоем без ответа сервера или ответом 5xx, клиентское приложение должно повторить запрос с тем же заголовком Idempotency-Key не более 3 раз; при ответе 4xx повтор не выполняется. | замечание D-010 |
| REQ-008 | Uploads one document image. Request body: multipart/form-data. | Когда клиент отправляет POST-запрос загрузки, сервер должен принять одно изображение документа или селфи, указанное в docType, и вернуть 201 Created. | замечание D-014 |

| REQ-020 | The upload endpoint responds within 3 seconds. | Когда сервер получает полный запрос загрузки документа, он должен вернуть окончательный ответ в течение 3 секунд после получения последнего байта тела запроса. | замечание D-035 |
| REQ-021 | Returns the verification status of the session. Authorization is not required for this endpoint so that the web landing page can poll it. | Когда клиент запрашивает статус сессии по её sessionId, система должна вернуть 200 OK со статусом сессии; если сессии с таким sessionId нет, система должна вернуть 404 Not Found с телом \{"error": "SESSION\_NOT\_FOUND"\}. | замечание D-040 |
| REQ-021 | Returns the verification status of the session. Authorization is not required for this endpoint so that the web landing page can poll it. | Когда приходит GET-запрос статуса сессии, система должна вернуть текущий статус сессии (DRAFT, SUBMITTED, PROCESSING, VERIFIED или REJECTED) в ответе 200 OK. | замечание D-041 |
| REQ-022 | Response 200 OK: \{"sessionId": "3f1c9a52-0000-4000-8000-000000000001", "status": "PROCESSING", "fullName": "TEST APPLICANT", "iin": "000000000000", "birthDate": "1990-01-01", "documentNumber": "000000000"\} | Когда клиент запрашивает статус сессии, система должна вернуть только sessionId и status, без ФИО, ИИН, даты рождения и номера документа. | замечание D-044 |
| REQ-024 | Removes a previously uploaded document. A document can be removed only while the session status is DRAFT; otherwise the server returns 400. | Когда клиент отправляет DELETE-запрос на удаление документа в сессии со статусом DRAFT, система должна удалить документ и вернуть 204 No Content; пока статус сессии не DRAFT, система должна вернуть 409 Conflict и не удалять документ. | замечание D-047 |
| REQ-024 | Removes a previously uploaded document. A document can be removed only while the session status is DRAFT; otherwise the server returns 400. | Когда клиент запрашивает удаление документа в сессии со статусом, отличным от DRAFT, система должна вернуть 409 Conflict и не удалять документ. | замечание D-048 |
| REQ-025 | Submits all uploaded documents for verification. The session must contain an ID card (both sides) or a passport, and one selfie; otherwise 400 with \{"error": "INCOMPLETE\_SET"\}. On success the status becomes SUBMITTED and the server returns 202 Accepted. | Когда клиент вызывает submit для сессии в статусе DRAFT с полным набором документов, система должна перевести сессию в SUBMITTED и вернуть 202 Accepted. Если сессия не в статусе DRAFT, система должна вернуть 409 Conflict и не запускать проверку повторно. | замечание D-049 |
| REQ-023 | Session status values: DRAFT, SUBMITTED, PROCESSING, VERIFIED, REJECTED. | Когда система отправляет запрос провайдеру верификации, она должна установить статус сессии PROCESSING; когда провайдер возвращает результат, система должна установить статус APPROVED или REJECTED в соответствии с этим результатом. | замечание D-056 |
| REQ-027 | 4.1. Minimum resolution of a document image is 1280×720 pixels; a selfie is at least 640×480 pixels. | Когда клиент загружает изображение документа, система должна проверить разрешение; если оно меньше 1280×720 пикселей, система должна вернуть 422 Unprocessable Entity и причину отказа в теле ответа. | замечание D-058 |
| REQ-029 | Liveness of the selfie is checked by the FaceCheck SDK 4.2 library on the server in a dedicated thread pool of 8 workers. | Когда клиент загружает селфи, система должна проверить живость лица на сервере. | замечание D-064 |
| REQ-032 | Limit: Uploads per session \| Value: at most 20 | Когда клиент загружает документ в сессию, система должна принять загрузку, если в сессии не более 19 загрузок; при 20 уже принятых загрузках система должна вернуть 409 Conflict и не создавать документ. | замечание D-070 |
| REQ-035 | 6.2. Images are stored encrypted with AES-256; keys are managed by the bank's HSM. | Пока документные изображения и селфи хранятся, система должна шифровать их алгоритмом AES-256. Ключи шифрования должны храниться в HSM банка в отдельном требовании 6.2b. | замечание D-077 |
| REQ-036 | 7.1. Every upload, deletion and status change is written to the audit log with sessionId, documentId, operation and timestamp. | Когда выполняется загрузка или удаление документа, система должна записать в журнал аудита sessionId, documentId, операцию и время в UTC; когда меняется статус сессии, система должна записать sessionId, операцию и время в UTC. | замечание D-078 |
| REQ-036 | 7.1. Every upload, deletion and status change is written to the audit log with sessionId, documentId, operation and timestamp. | Когда выполняется загрузка или удаление документа либо меняется статус сессии, система должна записать событие в журнал аудита до отправки ответа клиенту. | замечание D-081 |
