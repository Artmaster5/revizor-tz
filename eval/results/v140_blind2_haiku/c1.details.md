<a id="x-d-021"></a>
**D-021 · 🟡 MAJOR · Полнота.** Нет экрана для ответа 409 и кнопки «Повторить»

При ответе 409 (по карте уже есть активная заявка) экран не определён: клиент увидит общую ошибку или текст из API, и тестировщик не знает, что ожидать. Не сказано и то, какие параметры отправит повтор.

- Цитата: строка 52
- Как исправить: Указать соответствие ответов и экранов: 409 — экран с текстом «По карте уже оформлена заявка»; 401 — переход на вход; 404 — текст «Карта не найдена»; 500 — экран «Не удалось оформить заявку». Кнопка «Повторить» повторяет запрос с теми же параметрами.
- Как найдено: модель, проверка требования по критерию «полнота». Основание: ISO/IEC/IEEE 29148:2018, п. 5.2.5 — требование должно быть полным

<a id="x-d-022"></a>
**D-022 · 🟡 MAJOR · Реализуемость.** Повтор после ошибки сервера может привести к двойному списанию комиссии

Если сервер списал комиссию, но не создал заявку или ответ потерян, повторный запрос спишет комиссию ещё раз или вернёт 409. Идемпотентности в API нет, поэтому клиент получит разный результат при одинаковом действии.

- Цитаты:
  - строка 52
  - строка 84: «Время ответа метода создания заявки — не более 2 секунд для 95% запросов»
  - строка 93: «Идемпотентность запроса не требуется: повторный запрос по той же карте будет отклонён по правилу Ф-2»
- Как исправить: Добавить: «Кнопка «Повторить» отправляет запрос с тем же ключом идемпотентности (Idempotency-Key); повторный запрос с тем же ключом не списывает комиссию повторно и возвращает результат первого запроса».
- Как найдено: модель, проверка требования по критерию «реализуемость». Основание: ISO/IEC/IEEE 29148:2018, п. 5.2.5 — требование должно быть реализуемым
- Объединено с похожими замечаниями (3):
  - **Повтор после ошибки 500 конфликтует с правилом «повтор отклоняется»**. Экран ошибки показывает кнопку «Повторить». Но по требованиям повторный запрос по той же карте не идемпотентен и отклоняется ответом 409. Если первый запрос уже создал заявку и списал комиссию, клиент получит «По карте уже оформлена… строка 52: «При ошибке сервера показывается экран «Не удалось оформить заявку» с кнопкой «Повторить» (и ещё 1 цитата).
  - **Не описан повтор после ошибки или таймаута**. Экран ошибки предлагает кнопку «Повторить». Если первый запрос создал заявку, но клиент получил 500 или таймаут, повтор вернёт 409 без номера заявки. Клиент не узнает свою заявку, и поведение приложения не определено. строка 93: «повторный запрос по той же карте будет отклонён по правилу Ф-2» (и ещё 2 цитаты).
  - **Нет описания тайм-аутов и повторов при обращении к АБС и процессингу**. Документ задаёт только время ответа 2 с для 95% запросов. Не описано, что видит приложение, если АБС или процессинг не ответили за это время. Не указано, что делать при повторе запроса клиентом, когда первый запрос ещё выполняется… строка 84: «Время ответа метода создания заявки — не более 2 секунд для 95% запросов» (и ещё 1 цитата).
- Вопрос автору [В-08](#x-v-08)

<a id="x-d-027"></a>
**D-027 · 🟡 MAJOR · Проверяемость.** Критерий «ближайшее отделение» не определён

Тестировщик не знает, по какому расстоянию выбирать отделение, откуда брать координаты адреса и что делать при нескольких равных вариантах. Ожидаемый результат проверить нельзя.

- Цитаты:
  - строка 53
  - строка 47: «для отделения — список отделений из справочника»
- Как исправить: Задать правило: отделение с минимальным расстоянием по прямой от координат адреса доставки среди отделений из справочника BRANCHES; при равенстве — отделение с меньшим кодом.
- Как найдено: модель, проверка требования по критерию «проверяемость». Основание: ISO/IEC/IEEE 29148:2018, п. 5.2.5 — требование должно быть проверяемым
- Объединено с похожими замечаниями (2):
  - **Критерий «ближайшее» отделение не задан**. Разработчик может выбрать отделение по прямой, а тестировщик по маршруту. Клиенту могут назначить разные отделения, и тесты будут давать разные ожидаемые результаты. строка 53: «карта передаётся в ближайшее к адресу доставки отделение» (и ещё 2 цитаты).
  - **«Ближайшее к адресу доставки отделение» не определено**. При двух неудачных попытках курьера карта уходит в «ближайшее к адресу доставки отделение». Слово «ближайшее» не определено: по расстоянию, по справочнику или по выбору клиента. Правило есть только на экране, в Ф-требованиях его нет, и… строка 53: «карта передаётся в ближайшее к адресу доставки отделение, клиент получает push с адресом отделения» (и ещё 1 цитата).
