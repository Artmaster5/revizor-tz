При обрыве сети клиентское приложение или прокси повторит GET, и письмо уйдёт дважды. Не описаны тайм-аут АБС, число повторов, поведение при… строка 72: «REST type \| GET» (и ещё 1 цитата).
  - **В описании интерфейса не хватает правил надёжности**. Интерфейс меняет данные, но в документе не описано: тайм-ауты и повторы запросов; одновременные изменения одного объекта; идемпотентность изменяющих запросов. Без этих правил разработчики клиента и сервера по-разному поведут себя при… строка 72: «REST type \| GET».
  - И ещё 1: «Запрос, создающий файл и письмо, оформлен как GET»

<a id="x-v-01"></a>
**В-01.** Каким методом HTTP создавать выписку: POST или GET? (кому: архитектор или разработчик; к [D-093](#x-d-093), [D-095](#x-d-095), [D-105](#x-d-105))
- Почему важно: Запрос создаёт файл, пишет запись в statement\_request и может отправить письмо. GET по стандарту HTTP не должен менять состояние сервера. Прокси, браузер или повторный вызов могут создать лишние выписки и списать суточный лимит.
- Варианты ответа:
  - а) POST, параметры в теле запроса (рекомендуется) — что изменится: Метод и раздел REST переписываются на POST, параметры переносятся в тело.
  - б) POST, параметры в query, но без GET — что изменится: Метод меняется на POST, но query-параметры остаются, это нужно проверить с ИБ.
  - в) GET только для чтения готовой выписки, создание переносится в отдельный POST — что изменится: GET остаётся для чтения, добавляется отдельный POST для создания выписки.
- Если автор не ответит, считаем так: создание выписки выполняется методом POST, GET используется только для чтения готовой выписки.

Клиенту интеграции он не нужен, а при переименовании класса документ придётся менять без изменения контракта. Цитата модели: «Өріс: Controller \| Мәні: StatementController». Здесь он создаёт файл, пишет запись в statement\_request, отправляет письмо и расходует суточный лимит. Прокси, браузеры и кэши могут повторять такой запрос, и клиент… Цитата модели: «Өріс: REST type \| Мәні: GET». Почему снято: цитата не найдена в документе.
