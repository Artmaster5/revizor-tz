# Частичное изъятие средств со сберегательного депозита «Накопительный»

| Поле | Значение |
| :--- | :--- |
| Версия | 1.3 от 24.11.2026 |
| Автор | Ведущий системный аналитик направления «Сбережения» |
| Задача | DEP-731 |
| Системы | Мобильный банк, депозитный модуль АБС, сервис уведомлений |

## 1. Назначение и границы

1.1. Документ описывает частичное изъятие клиентом части суммы со сберегательного депозита «Накопительный» в мобильном банке без закрытия депозита.
1.2. В границы не входят: полное закрытие депозита, изъятие в отделении, депозиты в валюте, отличной от тенге.
1.3. Все даты и время в документе — по времени Астаны (UTC+5). Календарный день — с 00:00:00 до 23:59:59 по этому времени.

## 2. Термины

| Термин | Определение |
| :--- | :--- |
| Депозит | Сберегательный депозит «Накопительный» в тенге, открытый клиенту-физлицу |
| Неснижаемый остаток | Сумма, ниже которой остаток депозита не может опуститься в результате изъятия: 50 000 ₸ |
| Доступная сумма | Остаток депозита минус неснижаемый остаток минус сумма под арестом |
| Счёт зачисления | Текущий счёт клиента в тенге в этом банке |
| Изъятие | Одна операция перевода части остатка депозита на счёт зачисления |

## 3. Функциональные требования

**REQ-01.** Изъятие доступно только по депозиту в статусе «Действует». Для депозита в статусе «Арестован», «Закрыт» или «В процессе закрытия» кнопка «Изъять» не отображается, а API возвращает ошибку `DEPOSIT_NOT_ACTIVE`.

**REQ-02.** Сумма изъятия — целое число тенге от 1 000 ₸ до доступной суммы включительно.

**REQ-03.** После изъятия остаток депозита должен быть не меньше неснижаемого остатка (50 000 ₸). Запрос, нарушающий это правило, отклоняется с ошибкой `MIN_BALANCE_VIOLATION`, остаток не меняется.

**REQ-04.** Количество изъятий по одному депозиту — не более 2 в календарный месяц. Считаются только исполненные изъятия; отклонённые запросы в лимит не входят.

**REQ-05.** Третий запрос на изъятие в том же календарном месяце отклоняется с ошибкой `WITHDRAWAL_COUNT_EXCEEDED`. Счётчик обнуляется в 00:00:00 первого числа следующего месяца.

**REQ-06.** Деньги зачисляются только на счёт зачисления того же клиента. Зачисление на счёт другого лица или в другой банк не поддерживается.

**REQ-07.** Изъятие исполняется сразу: списание с депозита и зачисление на счёт выполняются в одной проводке АБС. Если проводка не прошла, ни депозит, ни счёт не изменяются, клиенту возвращается ошибка `POSTING_FAILED`.

**REQ-08.** Изъятие доступно круглосуточно, кроме регламентного окна закрытия операционного дня с 23:50 до 00:10. В это окно API возвращает ошибку `SERVICE_WINDOW`, клиенту показывается время, когда можно повторить.

**REQ-09.** Исполненное изъятие не отменяется. Чтобы вернуть деньги на депозит, клиент делает пополнение по правилам продукта.

**REQ-10.** Каждый запрос содержит ключ идемпотентности `requestId` (UUID). Повтор запроса с тем же `requestId` в течение 72 часов возвращает результат первого запроса и не создаёт новое изъятие.

**REQ-11.** Запросы на изъятие по одному депозиту обрабатываются строго последовательно. Второй запрос проверяется по остатку и счётчику, которые получились после первого.

**REQ-12.** После исполнения клиент получает push: сумма изъятия, новый остаток депозита и последние 4 цифры счёта зачисления. Сбой отправки push не отменяет изъятие.

**REQ-13.** Каждый запрос (исполненный и отклонённый) записывается в журнал аудита: идентификатор клиента, депозит, сумма, `requestId`, результат, код ошибки, время с точностью до миллисекунды. Журнал хранится 5 лет.

## 4. Вознаграждение

**REQ-14.** Вознаграждение начисляется ежедневно на остаток на конец календарного дня: остаток × годовая ставка / число дней в году (365 или 366). Результат округляется до 1 тиына по правилу «половина вверх».

**REQ-15.** Годовая ставка — 14,5 %, если остаток на конец дня не меньше 500 000 ₸, и 12,0 %, если меньше. Ставка определяется для каждого дня отдельно.

**REQ-16.** При изъятии в первые 90 дней с даты открытия (день открытия — первый день) вознаграждение, уже начисленное на изымаемую сумму, пересчитывается по ставке 1,0 % годовых.

**REQ-17.** Начисленное вознаграждение капитализируется в последний календарный день месяца.

## 5. Ошибки

| Код | HTTP | Условие | Текст для клиента |
| :--- | :--- | :--- | :--- |
| `DEPOSIT_NOT_ACTIVE` | 409 | Депозит не в статусе «Действует» | Изъятие по этому депозиту недоступно |
| `AMOUNT_TOO_SMALL` | 422 | Сумма меньше 1 000 ₸ | Минимальная сумма изъятия — 1 000 ₸ |
| `MIN_BALANCE_VIOLATION` | 422 | Сумма больше доступной суммы (остаток − 50 000 ₸ − сумма под арестом) | Можно изъять не больше {доступная сумма} ₸ |
| `WITHDRAWAL_COUNT_EXCEEDED` | 422 | Уже 2 исполненных изъятия в этом месяце | В этом месяце лимит изъятий исчерпан |
| `SERVICE_WINDOW` | 503 | Запрос в окне 23:50–00:10 | Повторите после 00:10 |
| `POSTING_FAILED` | 502 | АБС не провела операцию | Операция не выполнена, деньги остались на депозите |
| `TARGET_ACCOUNT_INVALID` | 422 | Счёт зачисления не принадлежит клиенту или открыт не в тенге | Выберите свой счёт в тенге |
| `VALIDATION_ERROR` | 400 | Нарушен формат полей запроса | Проверьте введённые данные |

## 6. API

`POST /api/v2/deposits/{depositId}/withdrawals`, авторизация — Bearer-токен сессии клиента. Депозит чужого клиента возвращает 404 без указания причины.

| Поле | Тип | Обязательно | Правило |
| :--- | :--- | :--- | :--- |
| `requestId` | string (UUID v4) | Да | Ключ идемпотентности, REQ-10 |
| `amount` | integer | Да | Тенге, 1 000 ≤ amount ≤ доступная сумма |
| `targetAccount` | string (IBAN KZ, 20 символов) | Да | Счёт зачисления клиента в тенге |

Успешный ответ — 201:

```json
{"withdrawalId":"wd-5c2e81","amount":"120000.00","depositBalance":"1380000.00","executedAt":"2026-11-24T14:05:31.204+05:00"}
```

Суммы в ответе (`amount`, `depositBalance`) — строки в тенге с двумя знаками после точки; `depositBalance` — остаток после изъятия.
Ответ с ошибкой содержит поля `code` (из таблицы раздела 5) и `message` (текст для клиента).

## 7. Интерфейс

7.1. Экран «Изъять»: поле «Сумма, ₸», под ним подсказка «Доступно: {доступная сумма} ₸», выбор счёта зачисления, кнопка «Изъять».
7.2. Кнопка «Изъять» неактивна, пока сумма меньше 1 000 ₸ или больше доступной суммы.
7.3. Перед исполнением показывается экран подтверждения с суммой, счётом зачисления и остатком после изъятия.
7.4. Если изъятие уменьшит ставку по REQ-15, на экране подтверждения показывается предупреждение с новой ставкой.

## 8. Нефункциональные требования

**NFR-01.** Время ответа метода изъятия — не более 2 секунд.
**NFR-02.** Доступность метода вне регламентного окна — не ниже 99,9 % за календарный месяц.
**NFR-03.** Номер счёта зачисления в журналах приложения маскируется: видны только последние 4 символа.

| AC-02 | Остаток 60 000 ₸ | Изъять 15 000 ₸ | 201, остаток 45 000 ₸ |
| AC-03 | Остаток 200 000 ₸ | Изъять 999 ₸ | 422 `AMOUNT_TOO_SMALL`, остаток 200 000 ₸ |
| AC-04 | Остаток 100 000 ₸ | Изъять 50 001 ₸ | 422 `MIN_BALANCE_VIOLATION`, остаток 100 000 ₸ |
| AC-05 | В ноябре уже 2 исполненных изъятия | Изъять 10 000 ₸ 30 ноября | 422 `MONTHLY_LIMIT`, остаток не изменился |
| AC-06 | В ноябре 2 исполненных изъятия | Изъять 10 000 ₸ 1 декабря в 00:15 | 201 |
| AC-07 | Запрос 1 исполнен | Повторить запрос с тем же `requestId` | Тот же ответ 201 и тот же `withdrawalId`, остаток уменьшен один раз |
| AC-08 | Остаток 200 000 ₸ | Два запроса по 100 000 ₸ одновременно с разными `requestId` | Один 201, второй 422 `MIN_BALANCE_VIOLATION`, остаток 100 000 ₸ |
| AC-09 | Депозит в статусе «Арестован» | Вызвать API изъятия | 409 `DEPOSIT_NOT_ACTIVE` |
| AC-10 | Время 23:55 | Изъять 10 000 ₸ | 503 `SERVICE_WINDOW` |
| AC-11 | АБС вернула отказ проводки | Изъять 10 000 ₸ | 502 `POSTING_FAILED`, остатки депозита и счёта не изменились |

| AC-13 | Чужой депозит | Вызвать API изъятия | 404 |
| AC-14 | Счёт зачисления принадлежит другому клиенту | Изъять 10 000 ₸ | 422 `TARGET_ACCOUNT_INVALID`, остаток не изменился |
| AC-15 | Сервис уведомлений недоступен | Изъять 10 000 ₸ | 201, изъятие исполнено, push не отправлен |
