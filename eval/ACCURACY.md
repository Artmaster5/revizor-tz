# Точность: как измеряли и что получилось

Все числа ниже получены на коде с тегом `v1.1.1`. Каждое число — один прогон. После замера на новых документах код не менялся.

Коротко:

- На документе организаторов глубокий режим (Opus) нашёл 40 из 52 дефектов ключа строго, независимый судья засчитал 41 полностью и 7 частично. Из 66 замечаний отчёта судья назвал ложным одно.
- На четырёх новых документах, которые агент раньше не видел, судья засчитал 49–50 дефектов из 55. Но шума там намного больше: ложным оказалось каждое четвёртое замечание на Haiku и каждое шестое на Opus.
- Агент завышает уровни: на новых документах он поставил «блокер» 18 раз (Haiku) и 21 раз (Opus), а в ключах блокеров 9.

## 1. Что такое «три числа»

Одно число легко подогнать, поэтому рядом всегда стоят три.

| Число | Кто считает | Что значит |
| :--- | :--- | :--- |
| **Строго** | программа `eval/score.py` | цитата замечания стоит на том же месте документа, что и дефект ключа, **и** в тексте замечания есть ключевые слова дефекта |
| **По месту** | программа | совпало только место. Это верхняя граница: замечание могло быть о другом на той же строке |
| **Судья** | ИИ-модель в отдельной сессии | читает документ, ключ и замечания отчёта и по каждому дефекту ставит «найден», «частично» или «не найден». Остальные замечания делит на настоящие, повторы и ложные тревоги |

Правила сопоставления записаны в шапке `eval/score.py`, задание судье — в [`judge/BRIEF.md`](judge/BRIEF.md).

Ложные тревоги считаются двумя способами. **Счётчик** программы — это замечания уровня «блокер» или «существенное», которые попали в место, названное в ключе хорошим. **Судья** смотрит все замечания, и мелкие тоже, поэтому у него ложных больше.

## 7. Что здесь слабое

- **Ключи писали не эксперты банка.** Ключ документа организаторов составила команда. Ключи новых документов — ИИ-помощник. Ни один ключ не полон: «настоящее замечание вне ключа» судья находит десятками.
- **Судья — ИИ-модель** (Claude Opus в отдельной сессии), а не человек. Он не видел наших оценок и переписки, но это тот же класс моделей, что и у агента. Каждый отчёт судил один судья, один раз.
- **Одно число — один прогон.** Разброс между прогонами есть: тот же документ организаторов на Haiku дал 37 из 52 строго в свежем прогоне и 40 из 52 в прогоне, где часть шагов взята из кэша.
- **Документ организаторов — не слепая проверка.** Агента отлаживали на нём. Честная оценка для незнакомого документа — раздел 5.
- **Строгий счёт зависит от слов.** Правильное замечание другими словами строго не засчитывается. Мы не добавляли ключевые слова после просмотра ответов агента, такие случаи решал судья.
- **Малая выборка.** 52 дефекта в одном документе, 64 в четырёх настроечных, 55 в четырёх новых.

## 8. Как повторить

Отчёты, оценки и вердикты судей лежат в `eval/results/`:

| Папка | Что в ней |
| :--- | :--- |
| `final_opus/` | сданный отчёт по документу организаторов, Opus |
| `before_v1.0.0/` | отчёт версии `v1.0.0` по тому же документу (строка «до» в разделе 3) |
| `haiku/` | тот же документ на модели по умолчанию |
| `gemini_free/` | бесплатный Gemini: первый прогон и повтор с кэшем |
| `tuning_haiku/` | четыре настроечных документа |
| `blind_haiku/`, `blind_opus/` | четыре новых документа |
| `*.offline.*` в корне | прогоны без модели, сводка в [`RESULTS.md`](RESULTS.md) |

В каждой папке: `<имя>.json` и `<имя>.md` — отчёт, `<имя>.score.txt` — сопоставление с ключом, `<имя>.judge.md` — вердикт судьи.

Пересчитать оценку программы (без модели и без ключей доступа):

```bash
python eval/score.py eval/results/final_opus/req.json --key eval/docs/requirements.md.key.json
python eval/score.py eval/results/final_opus/req.json --key eval/keys_v1/requirements.md.key.json
python eval/score.py eval/results/blind_haiku/b1.json --key eval/blind/b1_autopay.md.key.json
```

Собрать таблицы этого файла:

```bash
python eval/summarize.py eval/results/final_opus eval/results/haiku eval/results/gemini_free eval/results/tuning_haiku eval/results/blind_haiku eval/results/blind_opus
```

Проверить ключи на внутренние ошибки: `python eval/check_keys.py`.

Повторить прогон с моделью: `python main.py --input eval/blind/b1_autopay.md --output reports/my_b1.md --no-cache`. Числа будут немного другими: ответ модели не детерминирован.
