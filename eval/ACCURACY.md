# Точность: как измеряли и что получилось

Основные числа получены на версии 1.4.0 (ветка `wave9`, код замера — коммит `2a2060a`; более поздние правки меняют окно, документы и число вопросов, список замечаний не меняют). У каждого числа названа модель: **Opus — максимум, Sonnet — по умолчанию, Haiku — дешевле**. Разделы 3 и 4 описывают прежние версии (теги `v1.0.0`, `v1.1.0`, `v1.1.1`); версия названа у каждой таблицы.

Коротко:

- На документе организаторов Opus (максимум) нашёл 50 из 52 дефектов нашего списка по оценке независимого судьи, ещё 2 частично, пропусков нет; замечаний по делу 86 из 86. Строго по программе — 45 из 52.
- Sonnet (по умолчанию): судья засчитал 47, ещё 2 частично; замечаний по делу 86 из 87; полная проверка — 2 мин 48 с, $1.27 ≈ 582 ₸.
- Все десять пунктов организаторов найдены: программа насчитала 10 из 10 и на Sonnet, и на Opus.
- Блокеры ключа найдены все: 5 из 5 и на Sonnet, и на Opus.
- На документах, которых агент не видел: Sonnet — 102 из 109 (94 %) на 8 документах, Haiku — 155 из 165 (94 %) на 12 документах; сверка программой, строго.

## 1. Что такое «три числа»

Одно число легко подогнать, поэтому рядом всегда стоят три.

| Число | Кто считает | Что значит |
| :--- | :--- | :--- |
| **Строго** | программа `eval/score.py` | цитата замечания стоит на том же месте документа, что и дефект ключа, **и** в тексте замечания есть ключевые слова дефекта |
| **По месту** | программа | совпало только место. Это верхняя граница: замечание могло быть о другом на той же строке |
| **Судья** | ИИ-модель в отдельной сессии | читает документ, ключ и замечания отчёта и по каждому дефекту ставит «найден», «частично» или «не найден». Остальные замечания делит на настоящие, повторы и неверные |

Правила сопоставления записаны в шапке `eval/score.py`, задание судье — в [`judge/BRIEF.md`](judge/BRIEF.md).

**Как читать числа.** Ключи заморожены до прогона: после замера их не правят. Ключ документа организаторов составила команда, ключи новых документов — отдельные ИИ-помощники, не видевшие агента. Судья — независимая ИИ-модель в отдельной сессии: она не видела ни оценок программы, ни переписки, и для всех моделей она одна и та же с одним и тем же заданием. Числа «строго» и «по месту» — оценка программы; числа с пометкой «судья» — оценка судьи; в таблицах ниже это названо у каждой строки.

Без модели, только правила (бесплатно, 0,3 с): 23 замечания, 8 из 10 пунктов организаторов, 15 из 52 строго и 25 из 52 по месту. В версии 1.2.0 было 7 из 10 и 14 из 52; правил стало 47 (было 27). Судья этот прогон не оценивал.

Что сказал судья об отчёте Opus:

- Найдено 50 дефектов из 52, ещё 2 частично, пропусков нет. Все пять блокеров ключа найдены.
- Из десяти пунктов организаторов найдено 9, ещё один частично. Программа насчитала 10 из 10: судья строже.
- Замечаний по делу 86 из 86.

Что сказал судья об отчёте Sonnet:

- Найдено 47 дефектов из 52, ещё 2 частично. Все десять пунктов организаторов найдены полностью.
- Замечаний по делу 86 из 87.

Бесплатный Gemini (`gemini-flash-lite-latest`, прежняя версия, тег `v1.1.1`; у основной модели в тот день кончилась квота): 22 из 52 строго и 44 из 52 по месту, 9 из 10 пунктов организаторов, $0, 7 мин 17 с. На версии 1.4.0 Gemini не перемерялся.

## 3. До и после ночи улучшений

Сравнение идёт по **замороженному ключу v1** ([`keys_v1/`](keys_v1/README.md)): он остался таким, каким был в версии `v1.0.0`. В нём 4 блокера. Обе строки — Opus, один прогон.

| | v1.0.0 (до) | v1.1.1 (после) |
| :--- | :--- | :--- |
| Строго | 32 из 52 | 40 из 52 |
| По месту | 44 из 52 | 50 из 52 |
| Пункты организаторов, строго | 8 из 10 | 10 из 10 |
| Блокеры ключа, по месту | 4 из 4 | 4 из 4 |
| Судья: найдено / частично / не найдено | 29 / 9 / 14 | 41 / 7 / 4 |
| Судья: блокеров с завышенным уровнем | 2 | 0 |

Отчёт «до» и вердикт судьи по нему лежат в `eval/results/before_v1.0.0/`. Судья «до» работал с ключом v1, судья «после» — с ключом v2; дефекты в них одни и те же, отличается уровень одного дефекта. В паспорте отчёта «до» стоит коммит `d363ffa`: это тот же код, что тег `v1.0.0` (`a6714b9`). Позже коммит пересоздали, чтобы заменить адрес почты автора; файлы не менялись, номер коммита стал другим.

Полнота выросла: строгий счёт — с 32 до 40 из 52, судья засчитал полностью 41 дефект вместо 29.

### Изменение ключа

Рабочий ключ v2 (`eval/docs/requirements.md.key.json`) отличается от v1 одним дефектом: у D-28 (пустой раздел «Тестирование требований») уровень поднят с «существенного» до «блокера», потому что в образце организаторов это блокер, и переписано пояснение `why`. Дефекты, места и ключевые слова те же. Сам ключ после заморозки мы не правим. По ключу v2 блокеров 5, и сданный отчёт находит строго 3 из 5 (по месту 5 из 5).

## 7. Как повторить

Отчёты, оценки и вердикты судей лежат в `eval/results/`. Папки без приставки — прогоны прежних версий (тег `v1.1.1`), на них построены разделы 3 и 4. Папки `v140_*` — версия 1.4.0 (код замера — коммит `2a2060a`), на них построены разделы 1, 2, 5 и 6:

| Папка | Что в ней |
| :--- | :--- |
| `final_opus/` | сданный отчёт по документу организаторов, Opus (максимум) |
| `before_v1.0.0/` | отчёт версии `v1.0.0` по тому же документу (строка «до» в разделе 3) |
| `haiku/` | тот же документ на модели Haiku (дешевле) |
| `gemini_free/` | бесплатный Gemini: первый прогон и повтор с кэшем |
| `tuning_haiku/` | четыре настроечных документа |
| `blind_haiku/`, `blind_opus/` | четыре новых документа |
| `blind2_haiku/` | второй слепой набор: ещё четыре новых документа, только Haiku |
| `v140_opus/`, `v140_sonnet/` | версия 1.4.0, документ организаторов: отчёт, оценка программы (по рабочему ключу и по замороженному ключу v1) и вердикт судьи; Opus (максимум) и Sonnet (по умолчанию) |
| `v140_haiku/` | то же без вердикта судьи, Haiku (дешевле) |
| `v140_offline/` | версия 1.4.0 без модели, документ организаторов (строка «Без модели» в разделе 2) |
| `v140_blind_sonnet/`, `v140_blind_haiku/` | версия 1.4.0, первый набор незнакомых документов (`blind/`, 55 дефектов) |
| `v140_blind2_haiku/` | версия 1.4.0, второй набор (`blind2/`, 56 дефектов), только Haiku |
| `v140_blind3_sonnet/`, `v140_blind3_haiku/` | версия 1.4.0, третий набор с казахским и английским документами (`blind3/`, 54 дефекта; ключи и документы — в `eval/blind3/`) |
| `*.offline.*` в корне | прогоны без модели, сводка в [`RESULTS.md`](RESULTS.md) |

В каждой папке (в `v140_*` вердикт судьи есть только у документа организаторов на Opus и Sonnet): `<имя>.json` и `<имя>.md` — отчёт, `<имя>.score.txt` — сопоставление с рабочим ключом, `<имя>.judge.md` — вердикт судьи. Для документа организаторов есть ещё `<имя>.score_key_v1.txt` — сопоставление с замороженным ключом v1; в `before_v1.0.0/` есть только оно. В `gemini_free/` вердикта судьи нет: этот прогон не судили.

Пересчитать оценку программы (без модели и без ключей доступа):

```bash
python eval/score.py eval/results/final_opus/req.json --key eval/docs/requirements.md.key.json
python eval/score.py eval/results/final_opus/req.json --key eval/keys_v1/requirements.md.key.json
python eval/score.py eval/results/blind_haiku/b1.json --key eval/blind/b1_autopay.md.key.json
python eval/score.py eval/results/blind2_haiku/c1.json --key eval/blind2/c1_card_reissue.md.key.json
python eval/score.py eval/results/v140_sonnet/req.json --key eval/docs/requirements.md.key.json
python eval/score.py eval/results/v140_blind3_sonnet/d1.json --key eval/blind3/d1_prepayment.md.key.json
```

Собрать таблицы этого файла:

```bash
python eval/summarize.py eval/results/final_opus eval/results/haiku eval/results/gemini_free eval/results/tuning_haiku eval/results/blind_haiku eval/results/blind_opus
```

Проверить ключи на внутренние ошибки: `python eval/check_keys.py`.

Повторить прогон с моделью: `python main.py --input eval/blind/b1_autopay.md --output reports/my_b1.md --no-cache`. Числа будут немного другими: ответ модели не детерминирован.
