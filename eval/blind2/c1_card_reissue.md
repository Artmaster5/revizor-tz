### Цели
1. Дать клиенту возможность заказать перевыпуск дебетовой карты без визита в отделение.
2. Снизить количество обращений в отделения по перевыпуску карт на 30% за первый квартал после запуска.
3. Сократить время, в течение которого клиент остаётся без рабочей карты.

### Глоссарий
* **Действующая карта** — карта в статусе ACTIVE или TEMP_BLOCKED, срок действия которой не истёк.
* **Заявка на перевыпуск** — запись в CardsService, созданная после подтверждения клиентом экрана сводки.
* **Активная заявка** — заявка в статусе CREATED, IN_PRODUCTION или IN_DELIVERY.
* **Конечные статусы заявки** — ACTIVATED (новая карта активирована), CANCELLED (заявка отменена), FAILED (изготовление не удалось).
* **Курьерская служба** — внешний партнёр банка, доставляющий карты по адресу клиента.

### Архитектура решения
Мобильное приложение → API-шлюз → сервис карт (CardsService) → карточный процессинг.
CardsService → АБС (списание комиссии со счёта карты).
CardsService → сервис доставки → курьерская служба.
CardsService → сервис уведомлений.

### Дизайн процесса UI
Карты → выбрать карту → «Перевыпустить карту».

Экран 1. Выбор причины: «Утеряна», «Украдена», «Повреждена», «Истекает срок действия».
Пункт «Истекает срок действия» показывается, если до окончания срока действия карты осталось не более 60 дней.

Экран 2. Способ получения: «Курьер» или «Отделение». Для курьера — поле «Адрес доставки», для отделения — список отделений из справочника.

Экран 3. Сводка: причина, способ получения, сумма комиссии и кнопка «Подтвердить».

После подтверждения открывается экран «Заявка принята» с номером заявки и плановой датой получения.
При ошибке сервера показывается экран «Не удалось оформить заявку» с кнопкой «Повторить».
Если курьер не смог вручить карту за две попытки, карта передаётся в ближайшее к адресу доставки отделение, клиент получает push с адресом отделения.

### Требования к изменениям

#### BPMN схема процесса
Выбор карты → выбор причины → выбор способа получения → подтверждение → списание комиссии → создание заявки → блокировка старой карты (в зависимости от причины) → изготовление → доставка → активация новой карты → завершение.

#### Функциональные требования
* **Ф-1.** Перевыпуск доступен держателю действующей дебетовой карты, выпущенной на его имя. Для дополнительных карт и карт третьих лиц пункт «Перевыпустить карту» не отображается.
* **Ф-2.** По одной карте одновременно может существовать не более одной активной заявки.
* **Ф-3.** При причинах «Утеряна» и «Украдена» старая карта блокируется без возможности разблокировки в момент подтверждения заявки. При причинах «Повреждена» и «Истекает срок действия» старая карта продолжает работать до активации новой.
* **Ф-4.** Новая карта выпускается к тому же счёту. Номер карты меняется при причинах «Утеряна» и «Украдена» и сохраняется при остальных причинах.
* **Ф-4.** Комиссия за перевыпуск — 1 500 ₸ при причинах «Утеряна», «Украдена» и «Повреждена»; при причине «Истекает срок действия» перевыпуск бесплатный. Для премиальных карт перевыпуск бесплатный при любой причине.
* **Ф-5.** Комиссия списывается со счёта перевыпускаемой карты в момент подтверждения заявки.
* **Ф-6.** Клиент получает уведомления о смене статуса заявки по push, SMS и e-mail, видит статус заявки в разделе «Мои заявки» и может отменить заявку до передачи карты в производство.
* **Ф-7.** Срок доставки курьером — в кратчайшие сроки после изготовления карты. Получение в отделении — на 5-й рабочий день после подтверждения заявки.
* **Ф-8.** Заявки, подтверждённые до 16:00, передаются в производство в тот же рабочий день, подтверждённые после 16:00 — на следующий рабочий день.
* **Ф-9.** Клиент активирует новую карту в мобильном банке после получения; в момент активации старая карта закрывается.

### Sequence Diagram
Приложение → CardsService: создать заявку (cardId, reason, deliveryType, address или branchId).
CardsService → АБС: списать комиссию.
CardsService → процессинг: заказать изготовление карты.
Процессинг → CardsService: карта изготовлена.
Если процессинг вернул ошибку изготовления, заявка переходит в статус FAILED, комиссия возвращается на счёт карты в течение 1 рабочего дня.
CardsService → сервис доставки: передать карту на доставку.
CardsService → сервис уведомлений: сообщить клиенту новый статус заявки.
Процессинг блокирует старую карту только после активации новой карты клиентом, независимо от причины перевыпуска.

### Нефункциональные требования
* Сервис должен быть надёжным и выдерживать пиковые нагрузки.
* Время ответа метода создания заявки — не более 2 секунд для 95% запросов при нагрузке до 50 запросов в секунду.

### Требования к данным
* Хранить: идентификатор заявки, идентификатор карты, полный номер (PAN) и срок действия старой карты для сверки с процессингом, причину, способ получения, адрес или код отделения, сумму комиссии в тиынах, историю статусов с датой и временем.
* Заявки хранятся в таблице REISSUE_ORDERS в Oracle 19c с партиционированием по месяцу создания.
* Срок хранения заявок — 5 лет с даты перехода заявки в конечный статус.

### Требования к интеграции
Приложение создаёт заявку через дочерний документ «Перевыпуск карты — REST API».
Идемпотентность запроса не требуется: повторный запрос по той же карте будет отклонён по правилу Ф-2.

## Часть B. REST API

Дочерний документ части A: «Перевыпуск карты — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание заявки на перевыпуск карты. Функциональные требования: Ф-1 – Ф-9 |
| **REST type** | GET |
| **Authorization** | Bearer, сессия держателя карты |
| **Controller** | CardReissueController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `/cards/{cardId}/reissue` . Prod: `/api/v2/cards/{cardId}/reissue` |
| **CURL** | `curl -G "$BASE/cards/7f3a-55/reissue" -H "Authorization: Bearer $TOKEN" --data 'reason=LOST&deliveryType=BRANCH&branchId=ALA-014'` |
| **Swagger** | — |
| **Gitlab project** | cards/reissue-service |
| **Framework** | Spring Boot |
| **Author** | Аналитик команды «Карты» |
| **Developer** | Команда «Карты» |

### Логика работы метода
1. Проверить пользовательскую сессию.
2. Проверить, что карта принадлежит клиенту и является действующей дебетовой картой (Ф-1).
3. Проверить параметры запроса по таблице «Query-параметры».
4. Списать комиссию по правилу Ф-4 через АБС.
5. Проверить отсутствие активной заявки по карте (Ф-2); при наличии вернуть 409.
6. Создать заявку; при причине LOST заблокировать старую карту в процессинге.
7. Вернуть номер заявки, сумму комиссии и плановую дату получения.

### Особые правила
1. Причина EXPIRED принимается, если до окончания срока действия карты осталось не более 45 дней.
2. Параметр `address` обязателен при `deliveryType=COURIER` и не передаётся при `deliveryType=BRANCH`.
3. Параметр `branchId` обязателен при `deliveryType=BRANCH` и не передаётся при `deliveryType=COURIER`.

### Схема
```text
Приложение → CardReissueController → CardsService → АБС / процессинг → CardReissueController → приложение.
```

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |

### Ответ
Успешный результат — 201. Результаты 400, 401, 404, 409 и 500 — неуспешные.

| Parameter | Format | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- |
| `orderId` | string | UUID | Номер заявки | `order_id` |
| `status` | string | CREATED | Статус заявки | `status` |
| `fee` | integer | В тиынах, 0 для бесплатного перевыпуска | Списанная комиссия | `fee_tiyn` |
| `plannedDate` | string | YYYY-MM-DD | Плановая дата получения | `planned_date` |
| `trackNumber` | string | — | — | `track_number` |

### Статусы

**201.** Заявка создана.
```json
{"orderId":"0b6f2c1e-8d1a-4c55-9a51-2f3e7d9b1a40","status":"CREATED","fee":150000,"plannedDate":"2026-12-04","trackNumber":"KZ81220044"}
```

**400.** Параметры запроса заполнены неверно.
```json
{"message":"Некорректные параметры запроса"}
```

**401.** Запрос выполнен без действующей сессии.
```json
{"message":"Требуется вход"}
```

**404.** Карта не найдена или не принадлежит клиенту.
```json
{"message":"Карта не найдена"}
```

**409.** По карте уже есть активная заявка.
```json
{"message":"По карте уже оформлена заявка"}
```

**500.** Внутренняя ошибка сервиса.
```json
{"message":"Ошибка сервиса"}
```
