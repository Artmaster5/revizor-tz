# Частичное досрочное погашение потребительского кредита в мобильном банке

### Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Частичное досрочное погашение беззалогового потребительского кредита |
| **Продукт** | Мобильный банк для физических лиц |
| **Бизнес-процесс** | Обслуживание кредитов физических лиц |
| **Business owner** | Департамент розничного кредитования |
| **Product owner** | Управление цифровых продуктов |
| **Аналитик** | Отдел системного анализа, команда «Кредиты» |
| **Тип работы** | Новый функционал |
| **Влияние на ИС** | Мобильный банк, кредитный модуль АБС, сервис уведомлений |
| **Задача в JIRA** | LOAN-1472 |
| **Версия документа** | — |

### Цели
Сейчас клиент может досрочно погасить часть кредита только в отделении: в 2025 году так обработано около 38 000 заявлений,
среднее время визита — 40 минут. Цель — к концу II квартала 2027 года принимать не менее 70 % заявлений на частичное
досрочное погашение через мобильный банк.

### Термины
| Термин | Определение |
| :--- | :--- |
| Остаток основного долга | Непогашенная часть выданной суммы кредита без учёта начисленного вознаграждения и неустойки |
| Плановая дата | Дата очередного ежемесячного платежа по действующему графику погашения |
| Заявка | Распоряжение клиента на частичное досрочное погашение, принятое банком и ожидающее исполнения |
| Исполнение заявки | Списание суммы заявки и уменьшение остатка основного долга в АБС |

Все даты и время в документе — по времени Алматы (UTC+5).

### Рамки
Входит: беззалоговые потребительские кредиты в тенге, выданные физическим лицам, без просроченной задолженности.
Не входит: полное досрочное погашение (ведётся по задаче LOAN-1390), ипотека и автокредиты, изменение ставки вознаграждения.

### Архитектура решения
Мобильное приложение → API-шлюз → сервис досрочного погашения (PrepaymentService) → кредитный модуль АБС.
PrepaymentService → сервис уведомлений (push и SMS).

### Дизайн процесса UI
Кредиты → карточка кредита → «Погасить досрочно». Экран: остаток основного долга, поле «Сумма, ₸», переключатель
«Уменьшить платёж / Уменьшить срок», блок предварительного расчёта нового платежа, кнопка «Погасить».

### BPMN схема процесса
Выбор кредита → ввод суммы и способа пересчёта → предварительный расчёт → подтверждение → регистрация заявки →
исполнение в плановую дату → новый график → уведомление клиента.

### Функциональные требования
* **Ф-1.** Функция доступна клиенту, у которого есть хотя бы один действующий беззалоговый кредит в тенге без просроченной задолженности. Кредиты с просрочкой в списке видны, кнопка «Погасить досрочно» для них не показывается.
* **Ф-2.** Сумма частичного досрочного погашения — целое число тенге, не менее 10 000 ₸ и не более остатка основного долга.
* **Ф-3.** Заявка исполняется в ближайшую плановую дату. Подать заявку на эту плановую дату можно не позднее 23:00 предыдущего календарного дня; заявка, поданная позже, исполняется в следующую плановую дату.
* **Ф-4.** Клиент выбирает способ пересчёта: уменьшение ежемесячного платежа при сохранении срока или сокращение срока при сохранении платежа. Если клиент не изменил переключатель, по умолчанию сохраняется срок и уменьшается ежемесячный платёж.
* **Ф-5.** В плановую дату сумма заявки вместе с очередным ежемесячным платежом списывается с текущего счёта клиента в тенге.
* **Ф-6.** Новый ежемесячный платёж рассчитывается по формуле аннуитета от остатка основного долга после исполнения заявки, по действующей ставке и на оставшееся число месяцев.
* **Ф-7.** До подтверждения клиент видит предварительный расчёт: новый ежемесячный платёж или новую дату последнего платежа.
* **Ф-8.** На один кредит может быть не более одной заявки в статусе «Ожидает исполнения». Пока такая заявка есть, кнопка «Погасить досрочно» заменяется кнопкой «Отменить заявку».
* **Ф-9.** Клиент может отменить заявку не позднее 23:00 дня, предшествующего плановой дате. После этого времени отмена недоступна, кнопка «Отменить заявку» скрывается.
* **Ф-10.** После исполнения заявки клиент получает push-уведомление с суммой погашения и новым ежемесячным платежом (или новой датой последнего платежа); новый график доступен в карточке кредита.
* **Ф-11.** Кнопка «Погасить» на экране досрочного погашения — зелёная (#00A651), высота 48 px, шрифт Inter 16 pt, располагается внизу экрана над клавиатурой.
* **Ф-12.** Комиссия за частичное досрочное погашение не взимается.
* **Ф-13.** Когда заявка исполнена, клиенту направляется push-уведомление о сумме погашения и о новом размере платежа или сроке. Состав уведомления — см. п. 7.3.

### Sequence Diagram
Приложение → PrepaymentService: предварительный расчёт (loanId, amount, recalcMode).
Приложение → PrepaymentService: создать заявку. PrepaymentService → АБС: зарегистрировать заявку.
АБС → PrepaymentService (в плановую дату): заявка исполнена, новый график. PrepaymentService → сервис уведомлений: push.

### Нефункциональные требования
* Предварительный расчёт возвращается не более чем за 2 секунды для 95 % запросов при нагрузке до 50 запросов в секунду.
* Сервис должен выдерживать высокую нагрузку в дни массовых платежей и не допускать деградации.
* Все обращения к API журналируются с идентификатором клиента, loanId и Idempotency-Key.

### Требования к данным
Таблица `prepayment_request`: `id`, `loan_id`, `client_id`, `amount` (сумма в тиынах, bigint), `recalc_mode`, `status`
(`PENDING`, `EXECUTED`, `CANCELLED`, `REJECTED`), `planned_date`, `created_at`, `executed_at`, `new_payment` (тиыны, bigint).
Записи хранятся 5 лет после закрытия кредита.

### Требования к интеграции
Регистрация и исполнение заявки — через существующий метод АБС `LoanEarlyRepayment` (контракт ABS-API v3.2, раздел 4).
Ответ АБС об исполнении приходит в PrepaymentService сообщением в очередь `loan.prepayment.executed`.
Если в плановую дату заявка поступила в АБС до 18:00, она исполняется в тот же день; позже — в следующую плановую дату.

## REST API

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание заявки на частичное досрочное погашение |
| **REST type** | POST |
| **Authorization** | Bearer, сессия клиента — владельца кредита |
| **Controller** | PrepaymentController |
| **Request URL** | `/api/v1/loans/{loanId}/prepayments` |
| **Headers** | `Idempotency-Key` (UUID, обязателен) |

### Логика работы метода
1. Проверить сессию клиента и принадлежность кредита клиенту.
2. Проверить, что у кредита нет заявки в статусе `PENDING` и нет просрочки.
3. Проверить сумму и способ пересчёта.
4. Зарегистрировать заявку в АБС и сохранить её со статусом `PENDING`.
5. Повтор запроса с тем же `Idempotency-Key` в течение 24 часов возвращает исходный ответ без создания новой заявки.

### Параметры запроса

#### Path-параметры
| Parameter | Format | Mandatory | Description |
| :--- | :--- | :--- | :--- |
| `loanId` | string, 1–32 | Да | Идентификатор кредита в АБС |

#### Request body (`application/json`)
| Parameter | Format | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `amount` | integer | Да | 50 000–остаток долга | Сумма в тиынах | `amount` |
| `recalcMode` | string | Нет | `PAYMENT` / `TERM`, по умолчанию `TERM` | Способ пересчёта | `recalc_mode` |

Пример запроса:
```json
{"amount": 150000, "recalcMode": "PAYMENT"}
```

### Ответ
| Parameter | Format | Description |
| :--- | :--- | :--- |
| `requestId` | string | Идентификатор заявки |
| `status` | string | `PENDING` |
| `plannedDate` | string, `YYYY-MM-DD` | Плановая дата исполнения |
| `newPayment` | integer | Предварительный новый платёж, тиыны (при `PAYMENT`) |
| `newLastDate` | string, `YYYY-MM-DD` | Предварительная дата последнего платежа (при `TERM`) |

### Статусы
**201.** Заявка создана.
**400.** Сумма или способ пересчёта не прошли проверку: `{"code":"INVALID_AMOUNT","message":"Сумма вне допустимого диапазона"}`.
**401.** Нет действующей сессии.
**404.** Кредит не найден. Для кредита другого клиента тоже возвращается 404, чтобы не раскрывать его существование.
**409.** У кредита уже есть заявка `PENDING` или есть просрочка: `{"code":"PREPAYMENT_NOT_ALLOWED"}`.
**500.** Внутренняя ошибка; заявка не создаётся.

Отмена заявки описана в дочерней спецификации LOAN-1472-API-2 (метод `DELETE /api/v1/loans/{loanId}/prepayments/{requestId}`).

### Требования к тестированию
Тестирование проводится командой QA по стандартной методике банка. Тест-кейсы будут подготовлены после завершения разработки.

### Критерии приемки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Остаток основного долга 800 000 ₸, кредита с просрочкой нет | Подать заявку на 150 000 ₸, способ «Уменьшить платёж» | Заявка `PENDING`, в запросе `"amount": 150000`, показан новый платёж |
| Плановая дата 15.12.2026, заявка подана 14.12.2026 в 23:10 | Создать заявку | `plannedDate` = следующая плановая дата 15.01.2027 |
| Есть заявка `PENDING` на этот кредит | Создать вторую заявку | 409 `PREPAYMENT_NOT_ALLOWED` |
| Сумма 9 999 ₸ | Создать заявку | 400 `INVALID_AMOUNT` |
| Заявка исполнена в АБС | Получено сообщение `loan.prepayment.executed` | Статус `EXECUTED`, отправлен push, в карточке новый график |
